### 0.4 关键发现

## 一、决策点 1：命中率定义（核心）

### 1.1 候选定义对比

| 建议项 | 候选定义 A（宽松） | 候选定义 B（严格） | 候选定义 C（推荐） |
|---|---|---|---|
| 买入区间命中 | T+N 内任意一天收盘价在区间内 | T+N 内最低价 ≤ 买入上限 且 T+N 收盘价 ≥ 买入下限 | **T+N 内最低价 ≤ 买入上限 且 最高价 ≥ 买入下限**（价格曾进入区间） |
| 目标价命中 | T+N 收盘价 ≥ 目标价 | T+N 内最高价 ≥ 目标价 | **T+N 内最高价 ≥ 目标价**（价格曾达到目标） |
| 止损价命中 | T+N 收盘价 ≤ 止损价 | T+N 内最低价 ≤ 止损价 | **T+N 内最低价 ≤ 止损价**（价格曾跌破止损） |
| 止盈价命中（持仓） | T+N 收盘价 ≥ 止盈价 | T+N 内最高价 ≥ 止盈价 | **T+N 内最高价 ≥ 止盈价**（价格曾达到止盈位） |

### 1.2 意见：**推荐候选定义 C — 基于日内 high/low 的触及判定**

**理由：**

1. **符合交易实际**：投资者挂单买入/卖出时，只要价格触及委托价即可成交，不要求收盘价精确落在区间内。使用 high/low 判断"是否触及"更符合真实交易场景。

2. **数据可行性**：raw_kline 表包含 high/low 字段，且数据完整（已验证）。无需额外数据采集。

3. **与 005 算法设计对齐**：005 评审文档（review_005）中明确提到"买入区间下限 = 中枢 - ATR×0.5"，其设计意图是"价格回调到该区间时可买入"。使用 low ≤ buy_high 判断"是否曾进入买入区间"与算法设计意图一致。

4. **避免收盘价偶然性**：若仅用收盘价判断，可能因某日尾盘异动导致误判。high/low 覆盖全天价格波动，更稳健。

### 1.3 命中率定义细则

| 建议项 | 命中条件 | 统计口径 |
|---|---|---|
| **买入区间命中** | T+N 内存在任意一天，满足 `low ≤ buy_range_high` 且 `high ≥ buy_range_low` | 命中天数 / 总天数 |
| **目标价命中** | T+N 内存在任意一天，满足 `high ≥ target_price` | 命中天数 / 总天数 |
| **止损价命中** | T+N 内存在任意一天，满足 `low ≤ stop_loss` | 命中天数 / 总天数 |
| **止盈价命中（持仓）** | T+N 内存在任意一天，满足 `high ≥ take_profit` | 命中天数 / 总天数 |

**补充说明：**
- 买入区间命中与目标价命中可能同时发生（价格先进入买入区间，再上涨至目标价），两者独立统计。
- 止损价命中是**负面事件**，命中率高说明止损设置过紧或算法过于悲观。
- 对于"先触及止损价再反弹至目标价"的情况，两种命中均记录，但需在报告中标注"止损后反弹"案例。

## 二、决策点 2：回测方法推荐

### 2.1 候选方法对比

| 维度 | 方法 A：复用 backtest_results | 方法 B：新建独立回测 |
|---|---|---|
| **数据来源** | 已有 478 条记录（含模拟） | 遍历 raw_kline 历史数据，每 5 天生成一个回测点 |
| **评级来源** | 复用 ratings_history / 模拟评级 | 使用当前最新评级（与 run_historical_simulation 一致） |
| **技术指标** | 需历史回算（复杂） | 需历史回算（复杂） |
| **样本量** | 478 条（真实 247 + 模拟 324，有重叠） | 可生成 1000+ 条（27 只股票 × 60 天 / 5 天间隔） |
| **时间覆盖** | 2026-07-16 ~ 2026-07-28（真实）+ 60 天模拟 | 可覆盖全部 255 天历史 |
| **与现有回测一致性** | 高（复用同一批评级） | 中（新建回测点，评级可能不同） |
| **实现复杂度** | 低（复用已有数据） | 中（需写新回测函数） |
| **统计显著性** | 低（真实样本仅 13 天） | 高（可覆盖完整牛熊周期） |

### 2.2 意见：**推荐方法 B — 新建独立回测**

**理由：**

1. **样本量决定统计显著性**：方法 A 的真实评级样本仅覆盖 13 天（2026-07-16 ~ 2026-07-28），即使加上模拟数据，时间窗口也仅 60 天。价格建议的命中率需要跨越不同市场环境（震荡/上涨/下跌）才能得出可靠结论。方法 B 可覆盖全部 255 天历史数据，样本量提升 4-5 倍。

2. **与现有回测引擎解耦**：backtest_results 表的设计目标是验证"评级有效性"（评级变更后价格走势），而非"价格建议命中率"。两者验证对象不同：
   - 评级有效性：评级 → 未来 N 天收益率 → 判断评级是否正确
   - 价格建议命中率：价格建议 → 未来 N 天价格是否触及目标/止损 → 判断建议是否可行
   
   强行复用 backtest_results 会导致表结构膨胀（需新增大量价格建议相关字段），违背单一职责原则。

3. **方法 A 的致命缺陷**：backtest_results 中的模拟数据（is_simulated=1）使用 `load_stockdata_from_db` 构建 StockData，该函数返回的是**当前最新数据**（包括最新基本面/资金面/消息面），存在**前瞻偏差**。虽然 run_historical_simulation 的注释声称"对评估评级有效性可接受"，但对价格建议验证而言，前瞻偏差会导致目标价/止损价计算不准确，验证结果失真。

4. **方法 B 的技术可行性**：data_adapter 中的 `_calc_ma`、`_calc_bollinger` 等函数接受 closes 列表作为输入，只需截取历史时点之前的 K 线数据即可计算该时点的技术指标。技术门槛中等，但完全可行。

### 2.3 方法 B 的具体实现策略

**回测点生成规则：**
- 对每只股票，从第 35 个交易日开始（确保 MACD 可计算），每隔 5 个交易日取一个回测点
- 每个回测点截取该日之前的全部 K 线数据，计算技术指标（MA20/MA60/BOLL/ATR）
- 使用当前最新评级（与 run_historical_simulation 一致，避免评级历史变化带来的复杂性）
- 调用 price_advisor 算法生成价格建议
- 验证后续 T+5 / T+20 的价格走势是否命中

**与 run_historical_simulation 的关系：**
- run_historical_simulation 验证的是"评级 → 收益率"的有效性
- 007 回测验证的是"价格建议 → 价格触及"的有效性
- 两者可共享同一批回测点（相同的 stock_id + trade_date），但验证逻辑和输出指标完全不同

## 三、决策点 3：验证周期

### 3.1 候选周期对比

| 周期 | 说明 | 优势 | 劣势 |
|---|---|---|---|
| 仅 T+5 | 短期命中率（1周） | 快速反馈，适合短线策略 | 无法验证中期目标价可达性 |
| 仅 T+20 | 中期命中率（1月） | 验证中期目标价合理性 | 反馈周期长，止损可能早已触发 |
| **T+5 + T+20** | 双周期对比 | 全面评估短期/中期表现 | 计算量翻倍 |

### 3.2 意见：**推荐 T+5 + T+20 双周期**

**理由：**

1. **价格建议的双时间尺度特性**：
   - 买入区间和止损价是**短期概念**（1-2周内有效）
   - 目标价是**中期概念**（1个月内可达）
   - 仅用单一周期无法全面验证算法有效性

2. **与 005 算法设计对齐**：
   - 买入区间基于 MA20 + ATR，MA20 是 20 日均线，ATR 是 14 日平均波幅，两者都是中短期指标
   - 目标价基于 BOLL 上轨或 MA60，BOLL 周期 20 日，MA60 是 60 日均线，偏中期
   - T+5 验证买入区间/止损价的短期有效性，T+20 验证目标价的中期可达性

3. **参数微调的诊断价值**：
   - 若 T+5 买入区间命中率低但 T+20 目标价命中率高 → 买入区间设置过窄，可适当放宽 ATR 系数
   - 若 T+5 止损命中率高 → 止损设置过紧，需调整 ATR 系数或止损比例
   - 若 T+20 目标价命中率低 → 目标价设置过高，需调整目标涨幅映射

4. **计算成本可控**：27 只股票 × 50 个回测点 × 2 个周期 = 2700 次验证，SQLite 查询可在秒级完成。

## 四、决策点 4：输出指标清单

### 4.1 核心命中率指标

| 指标 | 定义 | 计算方式 |
|---|---|---|
| 买入区间命中率（T+5） | T+5 内价格曾进入买入区间的比例 | 命中次数 / 总回测点数 |
| 买入区间命中率（T+20） | T+20 内价格曾进入买入区间的比例 | 同上 |
| 目标价命中率（T+5） | T+5 内价格曾达到目标价的比例 | 同上 |
| 目标价命中率（T+20） | T+20 内价格曾达到目标价的比例 | 同上 |
| 止损价命中率（T+5） | T+5 内价格曾跌破止损价的比例 | 同上 |
| 止损价命中率（T+20） | T+20 内价格曾跌破止损价的比例 | 同上 |
| 止盈价命中率（T+5，持仓） | T+5 内价格曾达到止盈价的比例 | 同上 |
| 止盈价命中率（T+20，持仓） | T+20 内价格曾达到止盈价的比例 | 同上 |

### 4.2 时间效率指标

| 指标 | 定义 | 计算方式 |
|---|---|---|
| 平均达到买入区间天数 | 价格首次进入买入区间所需的平均交易日数 | 首次命中日期 - 回测点日期，取平均 |
| 平均达到目标价天数 | 价格首次达到目标价所需的平均交易日数 | 同上 |
| 平均触及止损价天数 | 价格首次跌破止损价所需的平均交易日数 | 同上 |
| 平均达到止盈价天数 | 价格首次达到止盈价所需的平均交易日数 | 同上 |

### 4.3 偏差分析指标

| 指标 | 定义 | 计算方式 |
|---|---|---|
| 目标价平均偏差 | 未命中目标价的案例中，目标价与实际最高价的平均差距 | (target_price - max_high) / target_price，取平均 |
| 止损价平均偏差 | 未触及止损价的案例中，止损价与实际最低价的平均差距 | (min_low - stop_loss) / stop_loss，取平均 |
| 买入区间宽度 | 买入区间上限与下限的相对宽度 | (buy_high - buy_low) / close，取平均 |

### 4.4 分组统计指标

| 分组维度 | 统计内容 |
|---|---|
| 分评级统计 | 各评级（强烈推荐买入/推荐买入/持有观望/建议减仓/强烈建议卖出）的命中率对比 |
| 分市场统计 | A股 vs 港股的命中率对比 |
| 分建议项统计 | 买入区间/目标价/止损价/止盈价的命中率对比 |
| 分周期统计 | T+5 vs T+20 的命中率对比 |

### 4.5 综合评估指标

| 指标 | 定义 | 计算方式 |
|---|---|---|
| 价格建议综合得分 | 加权平均各建议项命中率（目标价 40% + 买入区间 30% + 止损控制 30%） | 加权平均 |
| 风险收益比 | 目标价命中率 / 止损价命中率 | 比值，越高越好 |
| 建议可用率 | price_advice.available = true 的回测点比例 | 可用次数 / 总回测点数 |

## 五、决策点 5：实现方案

### 5.1 模块设计

**推荐：新建 `modules/price_backtest.py` 独立模块**

**理由：**
- 与现有模块化架构一致（backtest_engine.py 验证评级，price_backtest.py 验证价格建议）
- 物理隔离，避免与 backtest_engine.py 混淆
- 可独立测试、独立迭代

**模块结构：**

```
modules/price_backtest.py
├── _calc_historical_indicators()    # 历史时点技术指标计算
├── _calc_historical_atr()           # 历史时点 ATR 计算
├── _gen_price_advice_at_date()      # 在指定日期生成价格建议
├── _check_hit()                     # 命中判定（基于 high/low）
├── run_price_backtest()             # 主回测函数（遍历所有股票/回测点）
├── compute_price_backtest_report()  # 生成回测报告
└── PriceBacktestEngine 类           # 封装上述函数（可选，与 backtest_engine 对齐）
```

### 5.2 数据库设计

**推荐：新建 `price_backtest_results` 表**

**理由：**
- 与 backtest_results 表解耦，避免表结构膨胀
- 字段设计针对价格建议验证优化
- 不影响现有回测数据

**表结构：**

```sql
CREATE TABLE IF NOT EXISTS price_backtest_results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    stock_id INTEGER NOT NULL,
    backtest_date DATE NOT NULL,           -- 回测点日期
    rating TEXT NOT NULL,                  -- 评级（使用当前最新评级）
    market TEXT NOT NULL,
    
    -- 价格建议输出
    has_position INTEGER DEFAULT 0,        -- 0=无持仓, 1=有持仓
    buy_range_low REAL,
    buy_range_high REAL,
    target_price REAL,
    stop_loss REAL,
    take_profit REAL,                      -- 有持仓时有效
    position_pct INTEGER,
    
    -- 技术指标快照（用于审计）
    close_at_backtest REAL,
    ma20 REAL,
    ma60 REAL,
    boll_upper REAL,
    boll_lower REAL,
    atr REAL,
    
    -- T+5 验证结果
    t5_hit_buy_range INTEGER,              -- 1=命中, 0=未命中, NULL=数据不足
    t5_hit_target INTEGER,
    t5_hit_stop_loss INTEGER,
    t5_hit_take_profit INTEGER,
    t5_days_to_buy_range INTEGER,          -- 首次命中所需天数
    t5_days_to_target INTEGER,
    t5_days_to_stop_loss INTEGER,
    t5_days_to_take_profit INTEGER,
    t5_max_high REAL,                      -- T+5 内最高价
    t5_min_low REAL,                       -- T+5 内最低价
    
    -- T+20 验证结果
    t20_hit_buy_range INTEGER,
    t20_hit_target INTEGER,
    t20_hit_stop_loss INTEGER,
    t20_hit_take_profit INTEGER,
    t20_days_to_buy_range INTEGER,
    t20_days_to_target INTEGER,
    t20_days_to_stop_loss INTEGER,
    t20_days_to_take_profit INTEGER,
    t20_max_high REAL,
    t20_min_low REAL,
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_price_backtest_stock_date 
    ON price_backtest_results(stock_id, backtest_date);
CREATE INDEX IF NOT EXISTS idx_price_backtest_market
```

## 六、决策点 6：参数微调建议框架

### 6.1 微调触发条件

| 回测结果 | 诊断 | 微调建议 |
|---|---|---|
| 买入区间命中率 < 30% | 买入区间设置过窄 | 放宽 ATR 系数（0.5→0.7, 0.3→0.5） |
| 买入区间命中率 > 70% | 买入区间设置过宽 | 收窄 ATR 系数（0.5→0.3, 0.3→0.2） |
| 目标价命中率（T+20）< 20% | 目标价设置过高 | 降低目标涨幅映射（+20%→+15%） |
| 目标价命中率（T+20）> 60% | 目标价设置过低 | 提高目标涨幅映射（+20%→+25%） |
| 止损价命中率（T+5）> 40% | 止损设置过紧 | 放宽止损 ATR 系数（1.0→1.5）或降低止损比例 |
| 止损价命中率（T+5）< 10% | 止损设置过松 | 收紧止损 ATR 系数（1.0→0.8）或提高止损比例 |
| 止盈价命中率（T+20）< 30% | 止盈目标过高 | 降低目标涨幅映射 |
| 止盈价命中率（T+20）> 70% | 止盈目标过低 | 提高目标涨幅映射 |

### 6.2 微调优先级

| 优先级 | 参数 | 影响面 | 调整幅度建议 |
|---|---|---|---|
| P0 | 止损 ATR 系数（1.0） | 高（直接影响风险控制） | ±0.2 |
| P1 | 目标涨幅映射（+20%/+25%） | 高（直接影响收益预期） | ±5% |
| P2 | 买入区间 ATR 系数（0.5/0.3） | 中（影响买入时机） | ±0.2 |
| P3 | 止损比例映射（-7%/-8%） | 中（影响持仓风险控制） | ±2% |

### 6.3 微调验证流程

```
1. 运行 price_backtest，获取基线命中率
2. 根据 §6.1 诊断结果，确定微调参数和幅度
3. 修改 price_advisor.py 中的参数（需新开任务，007 不修改算法）
4. 重新运行 price_backtest，对比微调前后命中率
5. 若命中率提升且风险收益比改善 → 采纳微调
6. 若命中率下降或风险收益比恶化 → 回滚微调
```

### 6.4 微调红线

| 红线 | 说明 |
|---|---|
| 单次微调幅度不超过 ±20% | 避免参数震荡 |
| 微调后需重新回测验证 | 未经验证的微调不得上线 |
| 止损比例不得高于 -10% | 风险控制底线 |
| 目标涨幅不得低于 +5% | 收益预期底线 |

## 十、风险点和注意事项

### 10.1 技术风险

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 历史技术指标计算与最新计算存在偏差 | 中 | 使用相同的计算函数（_calc_ma/_calc_bollinger），仅输入数据不同（历史 K 线切片 vs 最新 K 线） |
| ATR 历史计算需要前 15 天数据，早期回测点可能数据不足 | 低 | 从第 35 个交易日开始取回测点，确保 ATR 可计算 |
| 回测点密度（每 5 天）可能导致样本重叠 | 低 | 统计时以回测点为单位，而非以天为单位，避免重复计算 |
| SQLite 查询性能（27 只股票 × 50 回测点 × 20 天验证窗口） | 低 | 使用索引（stock_id + backtest_date），查询优化 |

### 10.2 业务风险

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 使用当前最新评级进行历史回测，存在"未来函数"偏差 | 中 | 在报告中明确标注"评级使用当前最新值，非历史评级"，作为方案局限性说明 |
| 价格建议命中率受市场环境影响大，单一时间段回测可能失真 | 中 | 覆盖全部 255 天历史数据，包含不同市场环境 |
| 有持仓场景样本极少（仅 6 只股票） | 高 | 有持仓命中率仅作参考，不作为参数微调依据；重点验证无持仓场景 |

### 10.3 注意事项

1. **"未来函数"偏差说明**：007 方案使用当前最新评级进行历史回测，这与 run_historical_simulation 的策略一致。严格的历史回测应使用历史时点的实际评级，但 ratings_history 仅覆盖 13 天，无法支撑统计显著性。因此 007 方案是"评级有效性"与"价格建议有效性"的折中验证，需在报告中明确标注此局限性。

2. **ATR 历史计算的实现细节**：price_advisor._calc_atr 固定取最近 15 天数据，无法直接用于历史时点。007 方案需新建 `_calc_historical_atr(stock_id, end_date, period=14)` 函数，从 raw_kline 取 end_date 之前 15 天的数据计算 ATR。

3. **命中判定的边界情况**：若 T+N 窗口内价格同时触及止损价和目标价（先止损后反弹），两种命中均记录，但需在报告中单独统计"止损后反弹"案例，作为算法风险评估的参考。

4. **港股与 A 股的差异**：港股波动率通常高于 A 股，相同的 ATR 系数可能导致港股买入区间过宽。建议在报告中分市场统计命中率，若港股命中率显著低于 A 股，可考虑分市场参数微调（另开任务）。

## 十一、总体结论

### 11.1 推荐方案汇总

| 决策点 | 推荐 | 理由 |
|---|---|---|
| 1. 命中率定义 | **基于日内 high/low 的触及判定** | 符合交易实际，数据可行，与算法设计对齐 |

| 4. 输出指标 | 命中率 + 时间效率 + 偏差分析 + 分组统计 + 综合评估 | 多维度评估算法有效性 |
