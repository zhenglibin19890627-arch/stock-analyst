## 一、决策点裁定

### DP-1：重试取值方式 — **采纳 PM 倾向（移除硬编码，回归默认），不新增独立常量**

**裁定：采纳（修改细节）**

1. **移除 L1365 / L1430 的 `max_retries=1` 参数本身**（而非改成显式 `max_retries=3`）。理由：
   - `_http_get_em` 的 `rounds = max_retries if max_retries else MAX_RETRIES` 已实现"默认走 config"的集中管控语义，移除参数后自动回归 `MAX_RETRIES=3`，单一事实源在 config.py；
   - 显式传 3 会把数值再次散落进调用处，未来调整需两处同改，重蹈本次硬编码覆辙。
2. **不新增 `EM_MAX_RETRIES` 独立常量**。理由：
   - 当前无证据表明东财链路需要区别于全局的重试轮数；012 批次已论证 `MAX_RETRIES=3` 的全局合理性，本次只"释放"东财链路被压制的能力，不引入新配置面；
   - 若未来反爬加剧需要东财单独提轮数，届时在 **config.py** 新增 `EM_MAX_RETRIES`（集中管控原则，不放模块顶部），本批次不做预支设计。
3. 遵守约束：`config.py` 的 `MAX_RETRIES = 3` 不动。

### DP-2：错峰延迟的适用范围与取值 — **采纳 PM 倾向，限批量场景，2~5s**

**裁定：采纳**

1. **单只分析主链路（L2643 直接触发的单只采集）不加外部延迟**。理由：
   - 单只分析为用户实时触发，体验敏感；`_http_get_em` 内部已含每次直连尝试前 1.5~3.5s 随机延迟 + 轮间 1.5~3.5s 延迟，单次请求链路的错峰能力已足够（单只场景请求频次低，不构成反爬触发面）。
2. **错峰仅作用于 L1223 批量回退 EM 循环**：逐只之间 `time.sleep(random.uniform(2, 5))`，首只不延迟（循环前无请求，无需错峰）。
3. **取值 2~5s 合理，与内部轮间延迟不构成过度叠加**。理由：
   - 外部延迟（股票间）与内部延迟（同一股票的尝试间）作用在不同维度：前者防"逐只高频扫描"指纹，后者防"单点高频重试"指纹，二者正交；
   - 成功路径下每只内部延迟仅发生 1 次（1.5~3.5s），叠加外部 2~5s 后单只节奏约 7~10s，对 23 只规模的总时长影响可接受（见 DP-5）。
4. **不需要与 UA 轮换做额外协同**。理由：UA 轮换在 `_http_get_em` 内每次请求独立随机选取，天然与延迟解耦；"同一 UA + 固定间隔"才是反爬指纹，当前实现每次请求随机 UA + 随机延迟已满足。`random.uniform`（stdlib）即可，符合零代码约束。

### DP-3：连续失败退避策略 — **采纳（需要），两级机制：退避 + 熔断**

**裁定：采纳 PM 思路，细化为两级**

参照 `_THS_CONSECUTIVE_FAIL_COUNT` 既有模式（模块级常量 + 计数 + 成功重置），在回退循环内新增：

| 级别 | 触发条件 | 动作 | 常量（模块顶部，data_collector.py） |
|---|---|---|---|
| 退避 | 每发生 1 次失败 | 下一次股票间延迟 = `min(基础延迟 × 2^连续失败数, 30s)` | `_EM_BACKOFF_CAP_SECONDS = 30` |
| 冷却 | 连续失败 ≥ 3 只 | 额外暂停 60s 后继续 | `_EM_COOLDOWN_FAIL_N = 3`、`_EM_COOLDOWN_SECONDS = 60` |
| 熔断 | 连续失败 ≥ 5 只 | **提前终止本轮回退循环**，返回已采集的部分结果，日志明确记录熔断原因与剩余未采集清单 | `_EM_CIRCUIT_BREAK_N = 5` |

理由：

1. **熔断必须引入**：间歇性反爬窗口期内继续请求只会延长封禁窗口（反爬策略通常按"持续异常行为"计时），提前止损对成功率反而有利；
2. **熔断提前终止无数据风险**（依据 F-2）：剩余股票由日报主循环逐只 `fetch_capital_flow` 兜底重采，成功过的由"同日跳过"防重复。熔断不是放弃数据，是把采集时机后移；
3. 连续成功 1 只即重置计数（与 THS 模式一致），避免历史失败污染后续判断；
4. 阈值取值依据：23 只规模下，连续 3 失败已高度提示进入封禁窗口（间歇性反爬下单点偶发失败不会连续出现）；5 只是给"边缘抖动"留的缓冲余量。

### DP-4：分批参数取值 — **采纳（修改取值），仅作用于回退循环，参数放模块顶部**

**裁定：采纳框架，取值定为：批大小 5 只，批间间隔 `random.uniform(30, 60)` 秒**

1. **批大小 = 5**（PM 区间下限）。理由：反爬敏感期小批更安全；23 只 → 5 批（5/5/5/5/3），仅 4 次批间停顿，总时长增量可控。
2. **批间间隔 = 30~60s 随机**（PM 区间保留，取随机而非定值，避免固定节律指纹）。
3. **分批仅作用于 L1223 批量回退 EM 循环；日报主循环（逐只 `collect_stock_data`）不加分批**。采纳 PM 倾向，理由：主循环逐只串行采集 K 线/基本面/消息面/资金面四维，股票间天然有分钟级间隔，不构成密集请求面；且主循环受 012 超时框架管控，不宜再插入额外停顿。
4. **参数定义位置：data_collector.py 模块顶部常量**（与 `_THS_CAPITAL_CACHE_TTL`、`_THS_FAIL_THRESHOLD` 等既有先例一致），**不放 config.py**。理由：
   - 范围约束要求改动限于 `modules/data_collector.py`，放 config.py 将扩大改动面；
   - 这些参数是东财回退循环的实现细节，非用户可调的全局配置；未来若需热调再升级至 config.py。

最终常量清单（开发按此命名落地，均以 `_` 前缀表内部实现）：

```
_EM_INTER_DELAY_RANGE = (2.0, 5.0)     # 股票间基础错峰延迟（秒）
_EM_BATCH_SIZE = 5                     # 分批大小（只）
_EM_BATCH_GAP_RANGE = (30.0, 60.0)     # 批间间隔（秒）
_EM_BACKOFF_CAP_SECONDS = 30           # 退避延迟上限（秒）
_EM_COOLDOWN_FAIL_N = 3                # 冷却触发：连续失败只数
_EM_COOLDOWN_SECONDS = 60              # 冷却暂停时长（秒）
_EM_CIRCUIT_BREAK_N = 5                # 熔断触发：连续失败只数
_EM_FALLBACK_TOTAL_CAP_SECONDS = 600   # 回退循环整体软超时（见 DP-5）
```

### DP-5：最坏耗时与日报总时长兼容性 — **采纳"成功率优先"，增设回退循环整体软超时 600s**

**裁定：修改（增设整体超时上限），参数偏保守认可**

#### 5.1 单层 `_http_get_em` 最坏耗时复核（PM 估算复核结果：基本准确）

| 场景 | rounds=3 最坏 | rounds=1 最坏（现状） |
|---|---|---|
| 无系统代理（仅直连，每轮 1 次尝试） | 3×(3.5+15) + 2×3.5 = **62.5s** | 18.5s |
| 有代理（每轮代理+直连 2 次尝试） | 3×(15+3.5+15) + 2×3.5 = **107.5s** | 33.5s |

PM 估算"≈100s/只（3 轮）"对应有代理场景，复核成立；本机若无代理则实际最坏 62.5s。

#### 5.2 单只 `fetch_capital_flow` 最坏耗时（三层全失败）

- 无代理：push2his 62.5s + push2 62.5s + akshare 层 ≈15~30s ≈ **140~155s**
- 有代理：约 **230s**
- 正常成功路径（第 1 轮直连成功）：约 **4~6s**（内部延迟 1.5~3.5s + 响应 1~2s）

#### 5.3 批量回退场景全量 23 只估算（按最终参数）

| 场景 | 估算 | 说明 |
|---|---|---|
| 期望（多数成功） | **约 6~9 分钟** | 23×(成功 ~5s + 错峰 ~3.5s) ≈ 195s + 批间 4×45s ≈ 180s + 写库开销 |
| 熔断路径（进入封禁窗口全失败） | **约 6~8 分钟** | 连续 5 只失败即熔断：5×(62.5s+退避延迟) + 冷却 60s ≈ 350~450s，其后终止 |
| 无熔断理论最坏 | ~60 分钟（23×155s） | **不可接受 → 熔断 + 整体软超时双保险封死** |
| **有保护的实际最坏** | **≤ 约 11 分钟** | 受 `_EM_FALLBACK_TOTAL_CAP_SECONDS = 600` 封顶（每只处理完后检查已用时，超限则终止剩余），加在途单只耗时余量 |

#### 5.4 与日报总时长兼容性结论

1. **回退循环仅在 THS 批量源完全失败时触发**（`_fetch_capital_flow_ths_batch` 含 1 次重试 + 备选接口 + 1 小时缓存，常态命中），属低频降级路径，对日报常态时长影响有限；
2. **必须增设回退循环整体软超时 600s**（依据 F-1：该循环在 012 的 `BATCH_TIMEOUT` 计时窗口之外，无兜底）。实现方式：循环内每只开始前检查 `time.time() - start > 600`，超限终止并在返回值 `source` 中标注；
3. 叠加后日报最坏总时长 ≈ 预取 ≤11min + 主循环 ≤`BATCH_TIMEOUT` 30min ≈ **41 分钟封顶**，且主循环内失败股票由 90s 单只超时逐只止损，可接受；
4. **"宁可慢、保成功率"裁定成立**：东财主力净流入是唯一真实来源（018 已确立口径），资金面数据缺失直接影响评分可信度，错峰/分批/冷却的时长代价换取封禁窗口规避，方向正确。
