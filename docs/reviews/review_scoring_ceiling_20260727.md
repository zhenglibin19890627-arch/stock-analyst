## 一、方案 O2-A：资金面子项上限提升

### 1.1 方案摘要

| 子项函数 | 档位 | 原值 | 目标值 | 改动行 |
|---|---|---|---|---|
| score_north_capital | 北向大幅买入(north≥3000) | 85 | 88 | L771 |
| score_margin_capital | 融资大幅增加(margin≥2000) | 85 | 88 | L792 |

PM 评估风险：低，仅提升极端优异数据的得分，中性档不变。

### 1.2 技术可行性：可行

改动点明确，位于子项评分函数返回值内，符合红线 R5。不触碰降级机制（[adjust_subitem_weight](file://../../modules/scoring_engine.py#L216) 只读取 SubItem 配置）。

### 1.3 实证效果分析

| 子项 | 数据覆盖率 | 极端档触发概率 | 实际效果 |
|---|---|---|---|
| north_capital | **0%**（B26: 自2024-08-16停更） | 0%（100%走缺失中性分65） | **形同虚设** |
| margin_capital | 87.7%（B26回填后） | 低（margin≥2000万属极端） | 有限 |

> north_capital 档位 85→88 实际**永远不触发**，因为 north_net_buy 100%为 None，走 [L767 缺失中性分65](file://../../modules/scoring_engine.py#L767)。

### 1.4 风险评估

- **不会导致劣质股虚高**：仅影响极端资金流入档位。
- **降级机制不受影响**：权重调整函数不涉及子项返回值。
- **但实际效果极有限**：margin 档触发时总分提升 ≈ 3分 × 0.36 × 0.40 ≈ +0.4分。

### 1.5 红线检查：✅ 全部通过

### 1.6 意见：**建议修改**

PM 只改极端档位，但真正压制资金面天花板的是**缺失中性分**。建议追加：

| 改动项 | 原值 | 建议值 | 理由 |
|---|---|---|---|
| north_capital 缺失中性分 (L767) | 65 | **70** | north 100%缺失，每只股票都吃65分，压制维度分 |
| margin_capital 缺失中性分 (L788) | 63 | **68** | 缺失时拉低维度分 |
| main_capital 小幅流入档 (L753) | 82 | **85** | 0~1000万是最常见档位，提升基准 |

效果计算（north 100%缺失场景）：
- north 中性 65→70：+5 × ~0.08 × 0.40 ≈ **+0.16分/股**
- margin 中性 63→68（缺失时）：+5 × ~0.28 × 0.40 ≈ **+0.56分/股**
- main_capital 82→85：+3 × ~0.64 × 0.40 ≈ **+0.77分/股**
- 原始极端档 85→88：**+0.4分**（仅margin有数据时）
- **合计 ≈ +1.9分/股**，影响所有股票

## 三、方案 O2-C：盈利能力 gross_margin 缺失处理

### 3.1 方案摘要

score_profitability 当 gross_margin 缺失时提升 roe 权重，理由：gross_margin 数据源100%缺失（akshare限制），均值逻辑下 roe 被稀释。

### 3.2 技术可行性：**前提不成立，改动无效**

PM 的核心论据——"当前均值逻辑下 roe 被缺失的 gross_margin 稀释"——**经代码验证为错误判断**。

[score_profitability](file://../../modules/scoring_engine.py#L535-L583) 实际逻辑（L535-583）：

```python
scores = []
if roe is not None:  # L541: roe有值 -> 加入scores
    scores.append(roe_s)
if gross_margin is not None:  # L562: gross_margin=None -> 跳过，不加入scores
    scores.append(gm_s)
return _clamp(sum(scores) / len(scores), ...)  # 只有roe时 = roe_s本身
```

数据链验证：
- [data_contract.py L92](file://../../modules/data_contract.py#L92)：`gross_margin: Optional[float] = Field(default=None)`
- [data_adapter.py L419](file://../../modules/data_adapter.py#L419)：`gross_margin=fund.get('gross_margin') if fund else None`
- akshare 取不到销售毛利率 → DB 存 NULL → adapter 传入 None → `if gross_margin is not None` 为 **False** → gross_margin **完全不参与计算**

**结论：当前代码已正确处理 gross_margin 缺失，roe 从未被稀释。"提升 roe 权重"等同于在 `len(scores)==1` 时做 `sum/1`，改了等于没改。**

### 3.3 风险评估

N/A — 改动本身无效，不存在风险也不存在收益。

### 3.4 红线检查：技术上不触碰红线，但因前提错误无需执行。

### 3.5 意见：**否决**

PM 对 score_profitability 的机制理解有误。当前 `sum(scores)/len(scores)` 的动态均值逻辑已自动实现了"缺失字段不参与计算"。

**建议 PM 重新验证基本面均值偏低(50.7)的真实原因**——更可能是 roe 本身的数据质量/采集覆盖问题，而非 gross_margin 稀释。

## 四、方案 O2-D：资金面多日平滑（补充评审）

### 4.1 方案摘要

将 data_adapter.py L354-355 从"取最后1天"改为"取最近5天均值"：
- 原逻辑：`main_net_inflow = cap_rows[-1].get('main_net_inflow')`
- 新逻辑：`main_net_inflow = 最近5天 main_net_inflow 的均值`（不足5天用全部）

### 4.2 实证数据验证（架构师独立查库）

| 07-22 | -17900.0 | 大幅净流出 → 20分 |

#### 4.2.3 关键指标

| 被5日平滑"拯救"的股票（单日<-1000万 → 5日均≥-1000万） | **0只** |
| 5日均后大幅净流出增加 | +8只（+400%） |

### 4.3 Q1：阈值是否需同步调整？

**必须调整，否则区分度崩塌。**

当前 ±5000万/±1000万 阈值针对单日值设计。5日均值天然压缩极端值：
- 茅台单日+9491万（→95分）变成5日均-842万（→60分），**跨4个档位**
- 全表"大幅净流入"从14只锐减到7只

若保持阈值不变，5日后几乎所有股票挤在 -1000~1000万 区间，**评分区分度趋近于零**。

若改阈值（建议收紧至 ±2000万/±400万），又引入双重改动风险，且无回测验证。

### 4.4 Q2：防虚高风险

**风险存在且方向与PM预期相反。**

- 5日平滑后"大幅净流出"从2只暴增到10只，**更多股票被压低**
- A股资金面存在均值回归特性，5日平均会消除该信号
- 连续5天-3000万/天（趋势恶化）与剧烈波动但均值中性，5日均可能相近但含义完全不同

### 4.5 Q3：边界处理

PM 提出三种边界处理**逻辑正确**：不足5天用全部、None跳过取剩余、空数据保持None。✓

**实现陷阱**：`_read_capital_data` 返回正序（reverse后），`cap_rows[-1]` 是最新日。5日均值应取 `cap_rows[-5:]`（最后5个元素）。

### 4.6 Q4：改动范围

**PM 判断正确：只改 data_adapter.py，scoring_engine 零改动。**

契约不变（main_net_inflow 仍为 Optional[float]），评分函数不变。数据平滑属于数据预处理层职责。✓

### 4.7 Q5：north / margin 是否也要平滑？

| 字段 | 意见 | 理由 |
|---|---|---|
| north_net_buy | **不平滑**（同意PM） | 已降权0.10且100%停更，平滑无意义 |
| margin_balance_chg | **不平滑**（否决PM倾向） | L367-375 本身是存量差值计算，平滑语义模糊，且权重0.35风险高 |

### 4.8 意见：**否决**

**否决理由（三条，基于实证数据）：**

1. **方案目标无法达成**：全表 0 只股票被5日平滑拯救，PM 核心论据已被最新数据证伪。
2. **平滑效果反向**：5日后"大幅净流出"从2只增到10只（+400%），加剧而非缓解评分压制。
3. **引入隐性风险**：阈值失配导致区分度崩塌，需同步改阈值（双重改动），无回测数据支撑。

## 五、推荐替代方案 O2-E：调整维度权重

### 5.1 方案摘要

PM 的真实诉求是"优质股不被资金面短期波动拖累"。更优解法是**降权重而非平滑数据**。

调整 `config_weights.json` A股维度权重：

| 维度 | 原权重 | 建议权重 | 变化 | 理由 |
|---|---|---|---|---|
| kline（技术面） | 0.2507 | **0.28** | +0.0293 | 技术面数据完整度100%，评分稳定 |
| fundamental（基本面） | 0.2005 | **0.25** | +0.0495 | 基本面反映长期价值，匹配"低频交易"用户 |
| capital_flow（资金面） | 0.3985 | **0.30** | -0.0985 | 降低短期资金波动对总分的支配性影响 |
| news（消息面） | 0.1504 | **0.17** | +0.0196 | 消息面日均400+条已稳定运行 |

### 5.2 效果估算（以茅台为例）

- 资金面 0.40→0.30：即使资金面30分，拖累从 -12分 降至 -9分（**+3分**）
- 基本面 0.20→0.25：基本面良好(~75分)，多贡献 **+2.5分**
- **合计净提升 ≈ +5.5分**

### 5.3 优势对比

| 维度 | O2-D（5日平滑） | O2-E（调权重） |
|---|---|---|
| 改动文件 | data_adapter.py + 可能改 scoring_engine 阈值 | config_weights.json（1处） |
| scoring_engine 改动 | 需同步调阈值 | **零改动** |
| 区分度影响 | 崩塌（需重新校准阈值） | **不变** |
| 实证效果 | 0只股票被拯救 | **+5.5分/股** |
| 用户画像匹配 | 间接（数据平滑） | **直接**（降短期权重/升长期权重） |
| 回测验证 | 需要 | 可通过 B26 V4「评分不跨档」快速验证 |
| 红线触碰 | 无 | **无**（config_weights.json 不在任何红线内） |

### 5.4 实施建议

1. PM 签发 O2-E 任务书，限定只改 `config_weights.json` 的 `a_stock.weights`
2. 港股权重（`hk_stock.weights`）暂不动（港股资金面数据源不稳定，降权风险待评估）
3. `industry_overrides` 中各行业资金面权重同步从0.30~0.35降至0.25~0.30
4. 验收：跑全量自选股评分，确认（a）无跨档异常（b）优质股总分提升明显（c）劣质股不被虚高
