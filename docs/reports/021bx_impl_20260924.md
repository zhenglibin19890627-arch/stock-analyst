## 3. K6 盘口停更：根因诊断（定案）＋连通性健康提示

### 3.1 诊断过程与证据

| 步骤 | 结果 |
|---|---|
| data_status 取证 | orderbook failed 395 次全部为「mootdx实时行情获取失败」；最后成功 2026-09-09 14:24:28 |
| TCP 层 | 4 台备用池 IP（115.238.56.198:7709 等）**全部连通** |
| 应用层 | 4 台服务器 `Quotes.factory`+`quotes('000001')` **全部返回空载荷** |
| 全网层 | `bestip=True` 全网扫描（71s）选中的服务器同样空；`bars`（K线）与多股票复测一致为空 |
| 结论 | **TDX 服务端自 2026-09-10 起对 mootdx 0.11.7 客户端停止返回数据**（协议/服务策略变化），属采集源服务端问题，非本侧代码缺陷、非服务器池配置问题 |

### 3.2 处置（按队长裁定：纯网络环境问题 → 如实记录＋健康提示）

- **健康提示**：`blueprints/system.py` `_DIMENSION_META['orderbook']['desc']` 增补事实标注——
  断供起点、服务端空载荷实测、**「盘口为展示维度，评分链不消费，停更不影响评级（恢复后自动续采）」**
  降级声明；前端健康度面板「说明」列直接可见，防止用户把盘口红误读为评分链异常；
- **恢复路径**：mootdx 库升级（适配新协议）或 TDX 服务端恢复后，盘口采集与 mootdx K线降级
  自动恢复——无需代码改动；如后续升级 mootdx 需走 R17 依赖白名单流程另立任务；
- **不修理由**：本侧无代码可修（连通性已证、数据面为服务端拒绝）；评分不消费盘口，
  展示维降级可接受（t6 原判）。
