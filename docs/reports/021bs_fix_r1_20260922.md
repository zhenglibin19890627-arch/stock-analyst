## 1. 修复①（核心 P1-1）：迟滞保持态持续标注（B24 外层调和）

### 1.1 根因（比 t1 审计的定位更精确）

t1 审计定位为「rating_hysteresis 保持态无持续标注面」。实施时用只读 SQL 复核
300229 拓尔思（stock_id=100027）发现精确机制：

- `ratings_history`：09-14 分 52.7 保持「建议减仓」（迟滞压制，升档需 ≥53）、09-21
  分 49.7（合法建议减仓区间）、09-22 分 52.0 再次压制——**压制当日迟到滞说明本应生成**；
- 但 09-22 报告（generated_at 20:27）markdown **无**「迟滞」字样。原因：
  - `generate_advice` 的迟滞信息 `rating_hysteresis` 只放在**返回的 result dict**（advisor.py
    原 L1605），不写入 `analysis` dict；
  - 单股刷新路径 `_save_daily_report_for_advice` 用 `md_source = dict(analysis)` 调
    `_build_markdown_single`（020R-42），取不到 `rating_hysteresis` → **刷新/覆盖报告时
    迟滞说明静默丢失**（每日批次路径 daily_report.py L1142 传 result dict 不受影响）；
  - 拓尔思 09-22 报告正是 20:27 由刷新路径覆盖 16:10 批次报告 → 标注丢失。

### 1.2 修复设计（按 captain 批复的位置一：advisor 因子构建器 + 读取面消费方门控）

**共享判定面**（单一来源，与 apply_hysteresis 同阈值表）：

- `modules/rating_hysteresis.py` 新增纯函数 **`score_tier_mismatch_note(score, rating,
  market, margin=None)`**：按「总分所处档位区间 × 当前评级」判定失配并生成说明文字
  （含两档位名、迟滞口径、升/降档触发线=边界±margin）；一致或无法判定返回 `''`；
  文案无裸 `<`。阈值经 `get_effective_thresholds`（A股 80/65/50/30 / 港股 021R
  overrides 热加载），**不重实现边界映射**（R7/D4 合规）。**只产说明、不改评级**。

**四个落点（层层兜底，评级本身零改动）**：

| 面 | 位置 | 覆盖 |
|---|---|---|
| ① markdown 落库 | `advisor._build_markdown_single`：无 `rating_hysteresis` 时按失配现算追加「评级口径说明」行 | 新报告（两条生成路径）；顺带修复刷新路径丢压制说明的问题 |
| ② key_factors 落库 | `advisor._build_key_factors`：新增 `score_tier_note` 键 | 新报告（结构化面，随每次报告存在） |
| ③ 报告页读取面 | `blueprints/analysis.py`：新增 `_attach_score_tier_note`，接入实时增强（`_enrich_advice_result`）、`POST analyze`、快照路径（落库注记优先、缺失则同源现算） | **存量报告即刻带注记**（021BS 前生成的报告无需重生成） |
| ④ 看板评分卡读取面 | `blueprints/portfolio/watchlist_scores.py`：每股新增 `score_tier_note`（纯 GET 可观测） | 存量报告 + 审计脚本断言面 |

前端：`static/js/analysis.js` 评分卡在评级徽章/建议行下渲染 `score_tier_note` 横幅
（⚖️，渲染前转义防守）。

### 1.3 连带加固（必要前置）

`blueprints/analysis.py` 快照路径原样 `for dim_key, dim_data in key_factors.items()`
重建 dimensions——key_factors 里的非维度键：字符串值（score_tier_note）会令
`dim_data.get` **崩溃（500）**；字典值（021BQ 起的 `trader` 摘要）会伪造成 0 分
「维度」并可能污染最强/最弱维度。已收敛为**仅取四维规范键且值须为 dict**
（trader 伪维度副作用一并消除）。全库仅此一处 key_factors 遍历，其余消费方
（action_list / _derive_trader_signal / _derive_obos_signal / export）均为按键取用，安全。
