## 一、结论摘要

**根因**：东方财富 `push2his`/`push2`/`akshare` 三层接口服务器对当前出口 IP 实施**间歇性反爬阻断**（`RemoteDisconnected: Remote end closed connection without response`），**非永久封禁、非接口变更、非频率过高导致的永久封IP**。

**验证**：东财主站 `www.eastmoney.com` 可访问（HTTP 200），DNS/TCP 正常，仅 `push2his`/`push2` 子域在阻断窗口期内全部 `RemoteDisconnected`。通过**周期性重试（15秒间隔）**已成功恢复贵州茅台（600519）东财真实资金流数据，满足验收标准3。

**恢复方案**：增加东财采集的重试次数与时间间隔，利用"封禁窗口期"之间的空隙取回数据。现有代码在 `_fetch_capital_flow_em_individual` / `_fetch_capital_flow_em` 中设置 `max_retries=1`（仅1轮尝试），导致三层快速连续尝试全部命中阻断窗口，是本任务暴露的关键脆弱点。

**结论**：非个别股票失败，而是**全面性接口层阻断**。5只股票在测试时间段均无法访问 `push2his`，但先前另一诊断脚本（`diag_periodic_retry_019b.py`）在封禁窗口之外第1次即成功返回121条数据，证明**数据源本身健康，仅访问被间歇性阻断**。

## 三、Step 2：失败原因逐项排查

| 排查项 | 结果 | 说明 |
|---|---|---|
| 1. 请求头/反爬识别 | **非主因** | 已使用UA池（20+真实浏览器UA）+Referer+Accept，仍被断连；主站同UA访问正常 |
| 2. 代理配置 | **未失效** | 系统代理为空 `{}`，实际走直连；`_http_get_em` 智能回退逻辑正常 |
| 3. 接口地址 | **可访问** | DNS解析正常、TCP连接成功、`RemoteDisconnected` 发生在TLS握手后（服务器主动断连），主站 `www.eastmoney.com` 返回200 |
| 4. 频率限制 | **非主因** | 非429/403明确拒绝，而是连接被切断；间歇性出现，与请求频率无直接线性关系 |

**关键证据**：

1. **间歇性阻断**：`diag_retry_019b.py`（宁德时代6次重试）中，部分尝试成功、部分失败，非连续全部失败。
2. **主站可访问**：`www.eastmoney.com` 返回 HTTP 200，证明 IP 未被完全封禁，仅 `push2` 集群子域被限流。
3. **窗口期可恢复**：`diag_periodic_retry_019b.py` 第1次即成功（15秒间隔），`diag_session_reuse_019b.py` 复用Session 10次全部失败（间隔2秒）。→ **间隔越短越易命中阻断，间隔适中可避开**。
4. **现有代码脆弱点**：`_fetch_capital_flow_em_individual`（L1365）与 `_fetch_capital_flow_em`（L1430）均传 `max_retries=1`，`_http_get_em` 内 `rounds=1` 仅1轮直连尝试，三层快速连续尝试全部命中阻断窗口。

## 四、Step 3：替代数据源评估

| 方案 | 状态 | 数据质量 | 结论 |
|---|---|---|---|
| 同花顺批量源（`fetch_capital_flow_batch`） | **已落地** | 仅写辅助字段 `ths_net_inflow`，不写 `main_net_inflow` | 作为辅助指标保留，不冲突 |
| 东方财富 push2his（主源） | 间歇性阻断 | 最完整（主力/超大/大/中/小单分层 + 占比 + 收盘价） | **首选恢复对象** |
| 新浪/腾讯/网易估算源 | **已禁用**（P3-A决策） | 公式"成交额×涨跌幅/100"与真实主力无相关性 | 不可作为兜底，**维持禁用** |
| akshare 备用源 | 底层同用东财域名 | 同样被阻断 | 不可作为独立替代 |

**结论**：`main_net_inflow`（主力净流入分层数据）**仅东方财富提供**，无完全等价的独立替代源。同花顺仅提供 `ths_net_inflow` 辅助指标。**优先恢复东财源，维持估算源禁用**。

## 八、建议的后续优化（供PM决策，本次不改代码）

1. **提高东财采集重试次数**：将 `max_retries=1` 提升至 `max_retries=3`（复用 `_http_get_em` 已内置的多轮重试+随机延迟机制），显著提高命中窗口期概率。
2. **增加采集间隔错峰**：在 `fetch_capital_flow` 失败后，支持延迟重试（如15秒）而非快速连续三层尝试。
3. **多窗口采集**：对23只A股分批、错峰采集，避免同一窗口内密集请求。

> ⚠️ 以上为建议，未在本次改动中实施，需PM评估后另行排期。
