## 3. 新发现（R1 分级）

### F1【P1｜根因升格】迟滞保持态标注对「小数分数」失效——600519「重生成自愈」假设被否定

- **现象**：R1 审计存量 P1「R04 总评级×评分｜600519：总分 49.7 → 期望档建议减仓，
  实际评级持有观望，三层标注全缺」。t2/审计此前标注「重生成报告自愈」——
  **本复审实测否定**：2026-09-24 12:41 经 report-latest 重生成的当日报告
  （score=49.7/rating=持有观望）`key_factors`/`markdown` 依旧无任何标注
  （实测 `score_tier_note` 缺失、markdown 无「评级口径说明/迟滞」字样）。
- **根因（代码级定位）**：`modules/rating_hysteresis.py::_tier_for_score` 按档位表
  `[min, max]` 闭区间归类，而生效档位表为整数边界（持有观望 50–64、建议减仓 30–49）
  ——**49.7 落在 49–50 的表缝中 → 返回 None → `score_tier_mismatch_note` 返回 ''**。
  引擎本体 `_map_rating` 用连续判定（`score >= min`，49.7 → 建议减仓原始档），
  两处口径不一致；审计 R04 期望档与引擎一致（49.7 → 建议减仓），故 P1 判定正确。
  影响面：任何落在 (49,50)/(64,65)/(79,80) 表缝内的小数分数＋迟滞保持态报告都会
  静默缺标注——恰是迟滞最常发生的边界区。
- **对照**：600276 重生成（score=48.0，48 在 30–49 表内）标注三层齐全——同一端点
  同一路径，仅因分数是否落缝而不同，实证根因。
- **修复分级**：可代码修——`_tier_for_score` 改为与 `_map_rating` 同口径的连续判定
  （按 min 降序取首个 `score >= min` 的档位；或档位表 max 改连续如 49.99/浮点上界）。
  落点为 021BS 建立的展示层共享纯函数（非 B24 冻结面、不触 classify_stage/R7），
  需同步更新 `tests/test_score_tier_note_021bs.py`/selftest 用例＋审计 R04 回归。
  **本复审不代改（复审任务边界），移交实施任务＋批准。**
- **过渡建议**：在修复落地前，600519 报告页/看板对 49.7×持有观望无标注的状态将
  持续；可接受（分数与评级同屏，用户按评级执行不受影响——失配说明缺失属表述层
  风险而非指令矛盾）。

### F2【P2】回测样本覆盖缺口：15 只 08-28 后新增 A股零回测样本

- 实测：56 只中 **15 只**（002292/002881/002922/300204/300229/300497/300638/300687/
