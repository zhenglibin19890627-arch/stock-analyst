## 二、T1 候选权重方案设计评审

### 2.1 方案数量与设计空间裁定（评审要点 1）

**裁定：1~3 套候选 + 强制"现状权重"为控制组，成立。** 补充三点：

1. **控制组不是可选项而是第一比较基准**：T2 所有指标（IC、迁移、敏感性）必须全部以"现状权重重算"为对照列，候选方案只报告相对控制组的增量/差值——这与任务书 T2-2"现权重 vs 候选权重"表述一致，须显式列为"候选 0"。
2. **方案集单调递进**：多套候选应呈保守→激进梯度（如基本面 +5pp / +10pp 两档），不允许候选间方向相互矛盾（如一套上调资金面、一套下调资金面）——否则模拟报告无法向监理给出清晰的风险偏好选择面，也偏离 IC 报告方向性结论。
3. **每套候选 = 市场级 + 行业覆盖级两层的完整定义**（见开放项 A 裁定），只定义市场级而缺失行业层定义视为方案不完整。

### 2.2 开放项 B 裁定：单次调整幅度上限

**裁定：设限。单维度调整幅度 ≤±10 个百分点（绝对值），且自 07-27 回滚基线（现行值）累计计算。** 理由（只读核查支撑）：

- 样本 448 行/17 个交易日/29 只，019T T1 报告自证"所有 IC 结论仅方向性参考，不宣称统计显著"（R-1 硬约束）——大幅重排缺乏统计支撑。
- **评级跳档非线性放大（实测预演）**：在非行业覆盖 159 行上按 80/65 阈值预演"基本面 +10pp / 资金面 −10pp"，跳档行数 26 行、占 16.4%——±10pp 已是迁移规模不小的量级，再放宽将直接冲击前端展示与优化器基线（R-3/R-4）。
- O2-E 前车之鉴：上一轮失败调整即是大幅方向性改变且未验证；调幅越大，若与池特征反向则损害越大。
- 与既有工程约束同量级：M9 优化器自身 `MAX_WEIGHT_STEP = 0.05`（±5% 步进），019U 手动调整上限 ±10pp 恰为其 2 倍步进，量级协调、可追溯。

**实现要求**：候选权重定义后必须经过与生产一致的归一化路径（`_normalize_dim_weights`，不可用维度剔除、可用维度 min_weight=0.05 地板、比例归一至和=1）——候选方案声明的是"配置值"，各行实际生效权重因数据可用性而异，模拟必须逐行复算（见三-4）。

### 2.3 IC 证据到权重映射的方法论审查（评审要点 3）

**裁定：建立"两周期方向一致性"取舍规则，具体如下（019U 开发直接执行）：**

| 维度 | T+1（IC均值/ICIR） | T+5（IC均值/ICIR） | 方向一致性 | 019U 处理 |
|---|---|---|---|---|
| 基本面 | +0.0407 / 0.1608 | **+0.1716 / 0.5087** | 一致为正 | 唯一允许上调维度（候选内渐进，+5pp/+10pp 档） |
| 消息面 | +0.0034 / 0.0155 | **−0.2207 / −0.9630** | T+1 近零、T+5 负 | 维持观察，**不允许上调**（G2 红线） |
| 技术面 | −0.0960 / −0.2571 | −0.0255 / −0.0582 | 一致为负/近零 | 维持观察，不允许上调 |
| 资金面 | +0.0249 全样本 / **剔除填充行 +0.1150 / 0.4748** | −0.0720 全样本 / −0.0844 剔除 | **跨周期不一致** | 属"证据偏弱"而非"方向明确为负"：允许小幅让渡（≤5pp，仅让渡给基本面）或不动——两档均列入候选集交监理选择 |

**方法论要点（写进任务书执行要求）**：

1. **跨周期不一致维度的取舍原则**：只有当 T+1 与 T+5 方向一致（同正或同负）时，IC 证据才允许驱动该维度的方向性调整；方向不一致的维度一律按"弱证据"处理——可小幅让渡或不动，禁止利用单周期信号做大动作。此规则同时是 G2 防 O2-E 的直接实现（调整方向不得与任一周期证据相反）。
2. **资金面填充行口径**：剔除填充行后资金面 T+1 为正（0.1150）、T+5 仍负（−0.0844），跨周期不一致的结论在两种口径下均成立；候选评估必须沿用 019T T1 的填充行标记口径（`raw_capital_flow.main_net_inflow IS NULL`）并列披露（G4 门）。
3. **保守度声明**：每套候选的设计依据须引用 IC 报告数字，并附"受 R-1 样本量约束、仅供监理裁定参考"声明（任务书 T1-2 已有，确认保留）。
4. **诚实边界**：综合分 T+1/T+5 现均为弱负（−0.0685/−0.0890）——权重调整目标是改善综合分与未来收益的排序关系，但小样本下不得宣称"调整后 IC 转正即证明有效"；模拟报告只做相对优劣陈述（任务书 T2-4 已要求，确认）。

## 三、T2 模拟回测验证框架评审（本批次最高风险项）

### 3.1 方法有效性（评审要点 1，对应 R-2）

**裁定：模拟方案足以捕捉 O2-E 式"与股票池特征反向"信号——前提是复用 019T T1 的逐日横截面 Rank IC 管线，且叠加三项缓解设计。**

**为什么能拦住 O2-E**：O2-E 失败的本质是"权重向与本池未来收益负相关的维度倾斜"。本模拟对每套候选在**同一 448 行样本**上重算 total_score 并计算逐日横截面 Rank IC（T+1/T+5），凡与池特征反向的候选其综合分 IC 会在样本内直接劣于控制组——这正是 O2-E 当年缺失、本批补上的验证。**方法对目标失效模式敏感，结论：方法有效。**

**循环论证风险（"用答案验证答案"）——承认存在，按以下三件套缓解（P-3/P-5 强制）：**

1. **明示样本内验证并降级结论强度（必做）**：候选方案源自同一批样本的 IC 观察，模拟 IC 天然带选择偏差。报告扉页须声明"本模拟为样本内验证，仅用于候选方案间相对优劣排序，不构成统计显著结论；是否生效由监理依 R-1 约束裁定"。
2. **时间切分稳健性检验（必做，作附录）**：以 07-16~07-28（前 11 个交易日）为推导期、07-30~08-07（后 8 个交易日）为验证期，分别计算控制组与候选的综合分 IC。**已知局限须披露**：T+5 口径下验证期仅 2~3 个有效横截面（07-30/07-31 及 08-03 起的评分行尚无后续 K 线），切分检验是方向性参考而非通过闸门。
3. **留一股（LOO）稳健性（必做）**：对 23 只 A 股逐只剔除后重算每日 IC，统计"候选综合分 IC ≥ 控制组"的留一运行次数占比。稳健性判读：≥18/23 为稳健；15~17 为中等（候选仍可推荐但报告须披露敏感性）；<15 判定为脆弱（提示某几只股票驱动了候选优势，报告须披露是哪几只）。**G3 门按 15/23 设置。**

**候选方案过闸规则（G 门体系，供监理决策、防自动通过）：**

- **G1 主效门**：候选 T+5 综合分 IC 均值 ≥ 控制组，且 T+1 综合分 IC ≥ 控制组 − 0.02（不允许用 T+5 收益换 T+1 大幅恶化）。
- **G2 方向门（一票否决）**：候选任何维度的权重方向与 019T T1 方向性结论相反（上调 IC 为负/近零的维度，或下调唯一稳健正的维度）即淘汰。直接防 O2-E 复现。
- **G3 稳健门**：留一运行中候选 ≥ 控制组的次数 ≥ 15/23。
- **G4 敏感性门**：剔除填充行后，候选与控制组的相对排名不变（IC 均值口径）。

### 3.2 对比指标完备性（评审要点 2）

任务书三项指标（综合分 Rank IC、评级分布迁移、填充行敏感性）确认，**补充四类必做披露**：

1. **行业覆盖分层（P-4 强制，实证支撑）**：只读核查——A 股 367 行中 **208 行（56.7%）属于 7 个行业覆盖行业**（半导体 6 只/94 行、酿酒 2/33、医药制造 1/20、家电 1/19、通信设备 1/14、计算机设备 1/14、医疗服务 1/14），**市场级权重调整的直接生效面仅 159 行（43.3%）**。不披露分层，监理将无法判断一次权重调整到底影响了池子的哪一半。分层维度：覆盖行/非覆盖行 × 新旧权重的 IC 与迁移分别列示。
2. **评级迁移行级明细（P-4 强制）**：80/65/50/30 阈值下 5×5 跳档转移矩阵（行数级），并列出发生跳档的股票名+日期清单（前端展示影响面）；**另按 85/70（optimizer THRESHOLD_BASELINES）口径重复披露**——实测两口径现状分布差异显著（80/65：买入 74/观望 182；85/70：买入 33/观望 224），单口径披露不足以支撑 R-4 评估。
3. **模拟与存储基线一致性断言**：开发自测须证明"候选 0（现状权重）重算的 total_score 与逐日 IC 能复现 019T T1 报告数字"（IC 均值逐日一致）。实测 `total_score = Σ(维度分×权重) round 1 位` 在 367/367 行零失配，复算路径已证实可行——此断言是模拟可信度的锚点。
4. **候选间 delta 表**：各候选相对控制组的 IC 增量、迁移增量、填充敏感增量并列成表，供监理一页读完。

### 3.3 模拟口径冻结（评审要点 3）

**裁定（与 019T T1 完全一致，防口径漂移）：**

- 基准价 = `raw_kline` 中 `trade_date <= analysis_date` 的**最近一行收盘价**（兼容周末/补跑行）；T+n = 基准行之后**严格第 n 行**收盘价收益。与 `backtest_engine._get_tn_price` 约定一致（实测代码 L220-237：`trade_date > ? ORDER BY trade_date ASC LIMIT 1 OFFSET n-1`，语义等价）。
- T+1/T+5 两周期；**不加 T+20**（019T P-1 已裁定：0 可用样本）。
- 填充行口径 = `raw_capital_flow.main_net_inflow IS NULL`（实测 A 股 367 行中 144 行填充、占比 39.2%，T+1 口径 144/344=41.9% 与 IC 报告一致）。
- **样本快照冻结（P-5）**：模拟脚本执行时输出并写入报告头部——analysis_results 总行数/日期范围、A 股行数、raw_kline 末端日期、执行时间戳。实测当前快照：448 行（A 367/港股 81）、07-16~08-07、raw_kline 末端 08-07（08-07 后 0 行 → 当前 T+5 仅覆盖 ≤07-31 评分行，255 行口径）。**今日 16:10 后 raw_kline 与 analysis_results 均可能新增（08-10 交易日数据），执行时点不同快照行数不同——两种时点均合法，但须如实披露；若 16:10 后执行，08-03~08-07 部分评分行将获得 T+5 样本，报告中须注明这是快照红利而非方法差异。**
- **多权重制度陷阱（必须处理的实现细节）**：实测样本期内存在三个权重制度——07-16~07-22 代码默认值制度（0.25/0.25/0.10/0.40，70 行）、07-23~07-26 O2-E 期制度（0.2105/0.2632/0.1579/0.3684，56 行）、07-27 回滚后现行制度（0.2005/0.2507/0.1504/0.3985 及行业覆盖，89+ 行）。**模拟的"现权重"基线必须统一使用现行 config_weights.json（含 industry_overrides），对所有行从维度分重算 total_score，禁止使用存储权重做基线**（存储权重是历史制度痕迹，直接用会让"现权重"组混入三个制度）。存储权重的唯一合法用途是推断该行哪些维度参与了评分（weight>0 ⟺ 维度可用），候选重算时保持各行可用维度集合不变。

## 四、T3 权重生效与回滚预案评审

### 4.1 生效机制核实（评审要点 1）

**结论：任务书"修改后无需重启、下次分析自动生效"属实，无缓存例外——但存在一个静默回退风险点，必须纳入 T3 预案。**

代码核实（只读）：

- `scoring_engine._load_dim_weights`（L942-968）：**每次分析调用时重新打开并解析 config_weights.json**，无 lru_cache/模块级缓存（全文件 grep 确认无缓存点），行业覆盖优先（A 股 + industry 命中 → 直接用行业权重），异常回退 `_DEFAULT_DIM_WEIGHTS`（A 股 0.25/0.25/0.40/0.10）。
- 旧引擎 `analysis_engine._load_weights_config`（L36-62）与 `optimizer_engine._read_weights`（L554-582）同为每次调用读文件，热加载一致。
- ⚠️ **风险点：JSON 损坏/文件缺失时静默回退代码默认值，仅 warning 日志**。实测样本期 07-16~07-22 的 70 行正是代码默认权重组合（0.25/0.25/0.10/0.40）——该回退路径在本库历史上真实发生过。**T3 写配置后必须立即做两项校验**：①`json.load` 合法性；②只读调用 `_load_dim_weights('A', None)` 与 `('A', '半导体')` 确认返回新值。校验失败即回滚。
- 生效时点纪律：新分析才生效（历史 analysis_results / ratings_history 不追溯重算），生效时点避开 16:10/16:30 与周日 20:00（任务书已有，确认）。

### 4.3 开放项 C 裁定：监测频率、观察期与回滚触发规则

**预案如下（写入交付文档，作为 T3 条件触发后的长期机制）：**

2. **观察期**：生效日起 **≥4 周 且 新增 A 股评分行 ≥100 行**（先到先评估）。观察期内不因单期波动回滚。
3. **回滚触发规则（任一满足即回滚，恢复备份配置并记录）**：
   - R1：连续 2 个监测周期，新权重下综合分 T+5 IC 均值 < 模拟报告记录的控制组 T+5 IC − 0.05；
   - R2：任一被下调维度（如资金面）剔除填充行口径 T+1 IC 连续 2 期 < −0.10（方向反转实证）；
   - R3：被上调维度（基本面）T+5 IC 连续 2 期 < 0（支持证据消失）；
   - R4：结构性事件（行业级大面积数据缺失、归一化失效、配置损坏回退默认值）触发人工复核，由监理裁定。
4. **M9 耦合隔离**：监测报告须从 `strategy_params` 的 optimization_log（实测历史：5 条）识别 M9 自调整（±5% 步进、安全阀 1% 精度回滚），**M9 造成的权重变化先从监测口径中隔离再判定 019U 方向**，防止把 M9 反向调整误判为 019U 失效。

## 七、给开发的实施约束清单（19 条）

1. **候选方案**：候选 0（现状=控制组，含 industry_overrides 现行值）+ 1~3 套候选；每套含市场级与行业覆盖级完整定义；设计依据引用 IC 报告数字；附 R-1 声明。
2. **调幅上限**：单维度 ≤±10pp（自现行值累计），候选呈保守梯度排布；全部四维之和=1。
3. **方向规则**：仅基本面允许上调；消息面/技术面不动；资金面 ≤−5pp 让渡或不动（两档候选）；任何候选不得违反 G2。
4. **IC 管线复用**：逐日横截面 Rank IC，秩+Pearson 手工 Spearman；逐日 IC 序列并列披露；ICIR 带分母 n。
5. **收益口径**：基准价 = `trade_date <= analysis_date` 最近收盘；T+n = 严格第 n 行；仅 T+1/T+5。
6. **填充行口径**：`raw_capital_flow.main_net_inflow IS NULL` 标记，全样本/剔除并列披露。
7. **基线一致性断言**：候选 0 重算结果须逐日复现 019T T1 报告数字（开发自测必测项）。
8. **多制度陷阱**："现权重"基线统一用现行配置从维度分重算；存储权重仅用于推断维度可用集合（weight>0 ⟺ 可用）；重算取 round(1)。
9. **评级迁移**：80/65 与 85/70 双口径 5×5 转移矩阵 + 行级跳档清单（股票名+日期）。
10. **分层披露**：行业覆盖/非覆盖两组的 IC 与迁移分别列示。
11. **G 门报告**：G1-G4 逐门给出数字与判定，G2 不过即淘汰；报告不做"自动生效"式结论，优劣交监理。
12. **LOO 与切分**：留一股 23 次运行 ≥15/23 判定阈值；时间切分附录 + 已知局限披露。
13. **快照冻结**：报告头部记录 analysis_results 行数/日期范围/raw_kline 末端/执行时间戳。
14. **零侵入**：`mode=ro` SELECT 或 backup API 入内存；禁裸文件复制运行中 WAL 库；脚本放 `%TEMP%\opencode`、用完即删。
15. **零新依赖**：不 import scipy 等；pandas/numpy 仅有的计算依赖。
16. **T3 写配置**（仅监理裁定后）：写前备份 `config_weights.json.bak-YYYYMMDD`；写后 `json.load` 校验 + 只读调用 `_load_dim_weights` 双确认（市场级与行业级各一例）；更新 `_更新时间`/`_备注`。
17. **回滚文档**：交付文档含 4.2 节两行命令 + 预期输出；备份保留 ≥2 个历史版本。
18. **窗口纪律**：一切写操作避开 16:10/16:30 与周日 20:00；监测脚本避开周日 20:00。
19. **红线**：不触碰 advisor.generate_advice（B24）；禁止点击前端个股详情（B11）；不写生产库；不改 scoring_engine/optimizer_engine/backtest_engine 任何生产代码（本批纯研究 + 配置变更）。
