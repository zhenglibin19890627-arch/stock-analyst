### 1.5 判定

1. **数量自洽**：holdings 表、trade_records 全量重放、矩阵聚合三口径均为 **1,100 + 1,000 = 2,100 股**，无任何一笔流水在重放中产生数量分叉。矩阵"2,100 股"没有计算错误。
2. **成本不自洽（设计内）**：银河账面 61.046 为人工修正值（5 次留痕），纯流水口径为 61.3455。两种口径的聚合成本分别为 **57.53**（账面，矩阵在用）与 **57.69**（纯流水：121,148.62/2,100）。
3. **realized 残留 1 行**（见 1.4），需一次性重算清理（涉及写库，走用户批准 + R11 备份，本轮不执行）。
4. 若用户实际股数 ≠ 2,100：结论指向**流水漏录**（最可能是某账户存在未录入的卖出），核对方法见 §6。

## 3. 矩阵自洽性缺陷代码定位

### 3.1 缺陷 A（用户实测主矛盾）：买点共振行不受止损/阶段/评级门控 + 无触发日期

**现象**（live 实测 `/api/stocks/21/trader-advice`，2026-09-22 19:15）：

```
held_rows[0]  止损      收盘跌破 56.16 触发即无条件执行（这是纪律不是观点）   ← 现价 52.27，已触发
held_rows[1]  减仓检查  收盘已跌破 MA20（52.78）→ 按评级执行风控…
linkage[0]    买点侧共振成立（最高 5 星）→ 入场证据强于单信号：
              空仓者可按区间分批，持仓者持有                            ← 同屏矛盾
```

**代码定位**：`modules/trader_advisor.py` `signal_stage_linkage` **L645-649**：

```python
buy_res = signals.get('buy_resonances') or []
if buy_res:
    top = max(r['stars'] for r in buy_res)
    out.append(f'买点侧共振成立（最高 {top} 星）→ 入场证据强于单信号：'
               '空仓者可按区间分批，持仓者持有')
```

四个子缺陷：
1. **无日期**：共振对象其实带触发信息——`market_screener.py` L182 `sig_desc = 'label@date + ...'`（本例 `KDJ低位金叉@2026-09-21`），但该行只取 `stars`，日期被丢弃 → 窗口内历史触发读起来像新信号；
2. **无止损门控**：不消费 `close` 与止损线/MA20 的比较结果，纪律已触发时仍说"持仓者持有"；
3. **无阶段门控**：`buy_today` 行有弱势阶段分支（L617-619"反抽减仓/不接飞刀"），`buy_res` 行没有 → 若今日同时有 buy_today，同一 linkage 里会出现"反抽减仓"与"持仓者持有"两行互斥文案；
4. **无评级门控**：共振行不附相悖调和注记（buy_today×弱评级有 L653-655，共振行没有）。

**根因（窗口语义不一致）**：`_read_signals`（L195-231）把"今日命中"过滤（`trigger_date == kline_upto`，L221-227）只用于 `buy_today/sell_today`，`buy_resonances/sell_resonances` 却放行整个 3 日窗口（`detect_signals(window=3)`，market_screener L578-584）；行动清单 021BP 已按"仅今日命中"装配（action_list L233-239"窗口内历史命中：前日巡检已覆盖"），操盘手矩阵未继承同一纪律。实测滞留样本：无线传媒共振触发 09-18，09-22 仍显示"共振成立（5星）"。

**空仓侧同型问题**：`build_operations_matrix` L812-817「关注」行（`elif buy_top_stars >= 4`）同样不带日期（文案"等触发日落定"部分缓解但未引用实际触发日）。卖出侧 L640-644 共振行同无日期。

### 3.2 缺陷 B：矩阵行无"当前状态"评估

`build_operations_matrix` L719-764 装配的每一行都是"条件→动作"式（契约如此），但**不回填 close 与 level_value 的比较结果**：止损行文案"收盘跌破 56.16 触发即无条件执行"不标注"（当前 52.27，已触发）"。用户必须自己心算是否触发——实测中免 close 52.27 < 52.93 纪律线 且 < 56.16 价格建议止损，双破无标注。纪律行优先级最高是产品原则，但当前实现把"是否已触发"的判断成本转嫁给了用户。

### 3.3 缺陷 C：日报 trader 摘要时序——同一只股同日两个止损数字

实测同日并存：看板/报告 key_factors `top_action = "止损·52.93"`（纪律线口径），个股页 live 矩阵 `止损·56.16`（取高者口径）。

**代码定位**：`modules/daily_report.py` L1094-1164 的执行顺序——
1. L1094 `generate_advice()` → 其末尾 `_save_daily_report_for_advice`（advisor.py L629-742，019A 豁免）**先插入当日 daily 行，`price_advice=NULL`**（L729-730）；
2. L1105 `generate_price_advice()` 计算出价格建议（**仅内存，尚未写库**）；
3. L1126 `generate_trader_advice()` → `_gather_inputs`（trader_advisor L258-262）读"最新 ok daily"= **第 1 步刚插入的自身行，price_advice=NULL** → 价位层降级 → top_action 只剩纪律线 52.93；
4. L1148 `_save_report()` 按 R9 删除重插完整行（含 price_advice JSON），但 key_factors 里固化的是第 3 步算出的 52.93。

结果：**报告行内 price_advice.stop_loss=56.16 与 key_factors.trader.top_action=止损·52.93 自相矛盾**，且每天必然发生。

### 3.4 缺陷 D：price_advisor 单账户成本（021W 残留，双源止损混基数）

`modules/price_advisor.py` L344-383：`ORDER BY quantity DESC LIMIT 1` → 中免取银河 1,100@61.046（021BQ 修复前 trader_advisor 的同款缺口）。price_advice `cost_price=61.05`、`stop_loss=56.16`、`profit_pct=-14.4%`，与矩阵聚合口径（57.53、-9.1%）在同一张报告页同屏呈现，用户看到两个成本两个盈亏。该模块不在 B24 锁定范围（B24=advisor.generate_advice；price_advisor 是后处理模块，021BH 已有修改先例），可修。

### 3.5 缺陷 E：分歧检测不覆盖"持有观望"档

`detect_disagreement`（trader_advisor L476-491）只在 `_RATING_WEAK=('建议减仓','强烈建议卖出')`×好阶段、`_RATING_STRONG`×差阶段时报警。中免/汤臣/五粮液/恒瑞均为"持有观望"×下跌期/顶部出货区 → **不产生分歧标记**（`has_disagreement=False`），看板无任何提示——这是"三方矛盾"（行动清单无项 / 报告评级中性 / 操盘手阶段偏空）在代码层的空隙。属设计取舍（避免边界抖动），但对"纪律已触发"场景缺少兜底通道。

### 3.6 缺陷 F：已破止损持仓股在行动清单与预警两侧均静默

- 行动清单五路（评级/买点/卖点/预警/缺报）无"持仓纪律/止损触发"类目：中免今日零项（实测 `/api/dashboard/action-list`：评级未变、KDJ 触发日在 09-21 被今日过滤、预警全已读）。
- `alert_rules` 启用 5 类：rating_change / score_below(65) / capital_outflow / tech_signal / sell_signal——**无成本类/止损类规则**（alert_engine 具备成本百分比与动态止盈能力但无规则启用）。
- 价格建议卡已明确输出 `state=S4 已破止损、action_suggestion="建议止损"`，但该信号止步于个股页卡片，未进入行动清单/预警。

## 5. 修复方案（做 / 不做 / 怎么做）

### 5.1 【做·P0】矩阵行状态化——止损已触发必须显式标注

- **怎么做**：`build_operations_matrix` 为每行增加 `status` 字段（`'triggered' | 'pending' | None`）：close 与 `level_value` 可比较时回填；止损行 triggered 时 action 文案改「止损（已触发）」并附当前价（如「现价 52.27」），`top_action` 同步（如「止损·56.16（已触发）」）；前端 analysis.js 矩阵段按 status 加红色徽标。

### 5.2 【做·P0】共振行门控 + 补日期

## 6. 给用户的可核对口径说明（"2,100 股"核对清单）

**系统账本结论**：2,100 股 = 银河 1,100 + 东财 1,000，矩阵聚合无误；流水重放同口径亦为 2,100。请按以下步骤核对真实券商持仓：

1. **分账户看**（持仓页切账户，或对照两个券商 App）：
   - 银河证券中免应为 **1,100 股**；东财中免应为 **1,000 股**。
2. **数量对不上时查流水**（持仓页流水 tab / `GET /api/portfolio/holdings/21/trades`）：
   - 银河应有 12 笔：10 买 2 卖（2025-12-04 至 2026-09-18，清单见 §1.2）；
   - 东财应有 1 笔：2026-09-03 买 1,000@53.66（佣金 8.59，成本 53.6686 含佣）。
   - **若券商实际股数 < 系统数量 → 有卖出未录入**（最常见），补录卖出流水后系统自动重算；
   - **若券商实际股数 > 系统数量 → 有买入未录入**，同理补录。
