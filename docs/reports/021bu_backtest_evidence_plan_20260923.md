## 0. 结论速览

1. **核心证据复核成立**：当前位置分位仍是「推荐买入」档最强的条件化因子——
   A股动态窗口口径**低位 90%（9/10）vs 高位 42%（5/12），分化 +48pp**；
   T+5 固定周期同向（低位 69% (11/16) vs 高位 47% (7/15)，+22pp）。
   团队目标引用的「低位约 90% vs 高位约 42%」与当前库内真实数据一致。
2. **反向分化同样显著**：建议减仓档 T+5 **高位 90%（9/10）vs 低位 55%（34/62）**
   （-35pp）；且减仓档**低位**动态窗口命中仅 **38%（20/52，A 级样本）**——
   「低位减仓错杀提示」有 A 级样本支撑。
3. **价格建议（真实锚点 n=142，A股）**：买入区间 T+20 触及率 **92%（97/106，A 级）**、
   目标价 T+20 达成率 **29%（31/106，A 级）**、止损 T+20 触发率 **9%（13/142，A 级）**——
   三条均可直接入报告做预期管理注记。
4. **升降档后表现不支持"追升档"**：升档后 T+5 上涨占比 47%（n=87，A 级）≈随机；
   降档后 T+5 上涨占比 41%（n=82，A 级）、平均 -0.9%（弱信息）。→ **不入个股报告**（§3 O5）。
5. **样本诚实分级落地**：港股 140 条真实样本**无一个 A 级格**（n≥30）→ 港股全部展示项
   暂缓（§3 O8）；A股强烈推荐买入（n=1~2）/强烈建议卖出（n=4~8）均为 C 级 → 不展示百分数。
6. **引擎分层现状**：当前库内 670 条 A股真实样本**全部为 v5**（021AE 删除经典引擎后
   无 legacy 对照），「按引擎分层」暂无跨引擎结论可入报告，只做构成声明。

## 3. 报告优化项设计（做 / 不做 / 怎么做 + B24 落点 + 红线标注）

### O1【做】评级旁「历史命中徽章」（核心项）

- **内容**：评级档位旁展示「历史命中 69%（159/230）」格式（百分数必须带 n/m）。
- **口径**：`is_correct` 列（=回测中心市场报告分档表现同列同源）+ 市场过滤 +
  排除模拟行；T+1 主口径为主行，动态窗口为次行（可选）。
- **样本门槛（在共享函数内强制，而非前端约定）**：
  - A 级（n≥30）：返回 `acc` + `display='历史命中 69%（159/230）'`；
  - B 级（20–29）：同上 + `grade='B'`，前端渲染 ⚠样本偏小；
  - **C 级（<20）：`acc=None`、`display='样本不足（n=4）'`**——数据层就不给百分数，
    任何消费面都无法泄漏小样本命中率（诚实原则的实现锚点）。
- **共享函数（同源唯一真相）**：`modules/backtest_engine.py` 新增只读聚合纯函数
  `rating_evidence_for(market, rating) -> dict`（SELECT GROUP BY，单查询；
  门槛常量 `EVIDENCE_N_FULL=30 / EVIDENCE_N_PARTIAL=20` 与函数同处定义，
  审计脚本 import 同一常量）。放在 backtest_engine 的理由：矩阵/判定逻辑已有宿主、
  非 frozen 文件；与 `position_note_for` 同居便于复用 `POS_BANDS` 口径。
- **消费面（B24 合规落点）**：
  1. `blueprints/analysis.py` `/api/stocks/<id>/report-latest` 响应新增只读字段
     `rating_evidence`（现算，不写库）；
  2. `blueprints/portfolio/watchlist_scores.py` 看板评分卡每股新增 `rating_evidence`
     （每市场一次 GROUP BY 后查表，勿每股一查）；
  3. `static/js/analysis.js` 评级卡（score-hero 区域）+ `static/js/portfolio.js`
     评分卡 rating 旁小字渲染。
- **不做**：不写入 `daily_reports.markdown_content` / `key_factors`（见 O6）；
  不改 `advisor.generate_advice` 本体（B24）。
- **红线标注**：B24（落点全在读取面/展示层）；R7（不触碰评分引擎，评级判定零改动）；
  R20（A/H 分市场查询与展示）；诚实原则（C 级 acc=None）。

### O2【做】位置分化警示接入看板与报告页（复用已上线机制，不新造规则）

  `/api/stocks/<id>/position-note` + `analysis.js` posNoteBox 已上线（2026-09-18 回测提升②），
  文案含胜率与 n/m，符合诚实原则。
- **021BU 增量**：同一函数接入 ①看板 `watchlist_scores.py`（每股 `position_note` 字段，
  同源调用）；②报告页 `report-latest` 响应（`position_note` 字段）。**判定规则零改动**，

- **不做**：不改 `position_note_for` 判定门槛；不给 Markdown 落库（O6 同理由）。
- **红线标注**：B24（读取面）；R7（无评级判定变更）；分化门槛与审计共用常量。

### O3【做】价格建议卡「历史基准」注记（预期管理，全 A 级样本）

- **内容**（市场级聚合，真实锚点口径）：在价格建议卡（看板 pa_zone 卡 +
  报告页价格建议区）附一行——
  「历史基准（全市场真实评级样本）：买入区间 20 日内触及率 92%（97/106）·
  目标价达成率 29%（31/106）· 止损触发率 9%（13/142）」。
- **共享函数**：`backtest_engine.price_advice_evidence_summary(market) -> dict`
  （SELECT `price_backtest_results WHERE anchor_rating_date IS NOT NULL AND market=?`
  聚合 `t20_hit_buy_range/t20_hit_target/t20_hit_stop_loss`；同门槛常量分级）。
- **消费面**：同 O1 两响应 + 两 JS 渲染（同源函数，报告↔看板同值）。
- **不做**：按评级档细分展示（样本已 A 级但 v1 从简，二级迭代再开）；不改
  `price_advisor.py` 任何算法常量（021AJ/021AL 校准面不动）。
- **红线标注**：B24（纯展示）；R17（零新依赖）；数字必须来自共享函数现算（一致性 §4）。

### O4【做·规则而非独立元素】T+5 观望档口径注记

- 展示规则：任何展示面**不单独展示 T+5 固定周期命中率**；确需展示时必须带
  「观望档 1 周判定带 ±2%，跑出窄带属常态（021P），T+5 数字含口径伪影」注记。
  v1 徽章仅用 T+1 主口径 + 动态窗口，天然规避。

### O5【不做】升降档后表现入个股报告/看板

- 理由：①升档后 T+5 上涨占比 47%（A 级）≈随机——展示"升档后胜率"无信息量且易被
  读成「升档=会涨」的暗示；②降档后有弱信息（41%/-0.9%）但事件窗口重叠、同股聚类
  非独立样本，且把统计转译到个股语境违背分域契约（统计面≠指令面）；③T+20 两侧均
  C 级。→ 仅保留在回测中心域（查询脚本 + 可选的市场报告解读行），个股域零接入。

### O6【不做】命中率写入 markdown / key_factors 落库

- 理由：命中率随回测滚动更新，落库即成「冻结快照」，与读取面现算值产生
  stored-vs-live 漂移（021BS R2 N01 实锤教训：trader 摘要落库面丢失/漂移）；
  markdown 内数字与看板同屏打架是最典型 P1。**全部证据元素读取面现算、零落库**，
  一致性审计才有唯一基准（§4）。

### O7【不做】位置分位→仓位比例的量化映射

- 理由：现有证据（成对分化+命中率）不支持「位置→仓位%」的可信映射；`position_pct`
  由评级档位决定（B24/price_advisor 冻结面）；把 90%/42% 的分化直接翻译成仓位数字
  是过度解读（n=10/12）。O3 的客观注记（含止损触发率）已给用户决策参照，不给指令。

## 4. 看板一致性设计（同源同值）

**原则**：报告页与看板对同一证据项消费**同一个共享函数**（O1 `rating_evidence_for`、
O3 `price_advice_evidence_summary`、O2 既有 `position_note_for`），两者都是请求时现算，
无存储副本 → 结构上消除「同源不同值」。021BS 一致性审计机制（`audit_consistency_021bs.py`
r1 + `_r2`）作为回归守卫，新增规则如下（设计稿，供实施任务落地）：

### r1 脚本新增（audit_consistency_021bs.py，接 R01–R15 / F01–F05 之后）

| 规则 | 定义 | 分级 |
|---|---|---|
| **R16** 评级徽章三方同源 | ①report-latest 响应 `rating_evidence` ②watchlist-scores 响应 `rating_evidence` ③审计按生产同款 SQL（ro 直读）现算基准。三方 c/n 与 display 必须一致：同数据日不一致 = **P1**（数字打架）；徽章字段缺失（有报告/有评级时）= P2（应接未接，降级展示） | P1/P2 |
| **R17** 诚实原则展示门 | 任何响应/前端片段中出现的证据百分数必须伴随 `n/m`（或 n 在同对象内）；`grade='C'`（n<20）却出现百分数 = **P1**（小样本误导，诚实原则违规）；`acc` 非空但 n 缺失 = P1 | P1 |
| **R18** 价格基准注记同源 | 页面/响应中的「历史基准」数字 ≠ `price_advice_evidence_summary` 现算 = P1；非真实锚点口径（含重建点/全体）冒充主口径 = P2（需口径标注） | P1/P2 |
| **F06** 看板评分卡证据流 | watchlist-scores 每股 `rating_evidence`/`position_note` vs 审计现算基准（与 F05 同型流量核对）；不一致 = P1 | P1 |

> 规则编号接续 r1 审计脚本现有 R01–R15（新增审计规则记作 R16–R18、流量规则 F06；
> ⚠ 此编号属审计脚本命名空间，与 docs/RED_LINES.md 的红线 R16–R19 无关——文档与
> 实施注释中须写明「审计规则 R16」以免与红线 R16 混淆）。

### r2 脚本新增（audit_consistency_021bs_r2.py）

| 规则 | 定义 | 分级 |
|---|---|---|
| **N04** 反落库守卫 | `daily_reports.key_factors` / `markdown_content` 中不应存在落库的历史命中率数字（O6 设计）；发现形如「命中率/命中 xx%（n=…）」的存储副本 = P2（反漂移观察）；且其数字与现算不符 = **P1**（冻结快照已打架，违反读取面现算设计） | P2/P1 |

### selftest 合成用例（两脚本各自内置，不触库）

1. 构造 A（n=35）/B（n=25）/C（n=15）三档合成样本 → 断言 `rating_evidence_for` 的
   grade 与 C 级 `acc=None`（诚实门在数据层生效）；
2. 构造报告面/看板面/现算三方一致与不一致两组 → 断言 R16 判 P1 与 OK；
3. 构造 C 级带百分数的响应片段 → 断言 R17 判 P1；
4. 构造含落库命中率的 key_factors → 断言 N04 判 P2，数字失真时判 P1。

### 行动清单（action-list）：**不消费**证据元素

理由：021BR 分域契约——行动清单是**指令面**（纪律/评级/分歧置顶项），证据徽章是
**统计面**；统计数字进指令面会抬升每项的认知成本且无动作语义。看板评分卡与报告页
（结论展示域）承载证据即可。审计上表现为：action-list 响应不含 rating_evidence 键
（可在 r1 F01 附带 INFO 观察，不设门禁）。

### 刷新与缓存

- `watchlist-scores` 已有 ETag：`rating_evidence` 为确定性字段（随 DB 变化而变），
  自动参与 ETag 指纹，无 304 陈旧风险；
- `report-latest` 的证据字段为响应级现算，不触碰 021K 的 15 分钟重评写库路径
  （零新增写库点，R9/R10 不变量无涉）。
