## 一、测试用例（逐条出 PASS/FAIL + 证据）

### TC-019E-1 补采正向触发（任务 1）
1. 构造：专用日期下某股票仅占位行（main_net_inflow IS NULL）/ 估算行（is_estimated=1）/ 完全无行三种状态 → 触发 `fetch_capital_flow_batch`（可函数级调用）→ 三者均进入补采清单；已有真实数据（is_estimated=0 且 main NOT NULL）的不进清单
2. 代码核查：补采循环调用 `_em_batch_collect`，复用 `_EM_INTER_DELAY_RANGE`~`_EM_FALLBACK_TOTAL_CAP_SECONDS` 共享常量与 `_EM_CONSECUTIVE_FAIL_COUNT` 计数器，**无新增平行常量**
3. 日志核查：补采前缀 `[资金面补采]` 与 019C 回退前缀区分；入口 INFO 含触发来源标注
4. 回归核查：THS 批量失败走 019C 原回退路径的逻辑未被破坏（`_em_batch_collect(a_stock_symbols, log_prefix='EM回退')`）

### TC-019E-2 估算兜底写入与评分纯净（任务 2，★核心）
1. 核查 `fetch_capital_flow` 提前 return 已拆除：`em_all_failed = (saved_count == 0)` 标志位后继续执行估算降级链路（M-4）
2. 核查三处估算源（新浪/腾讯/网易）`if False` 已全部解除、无第四套估算启用路径、估算源网络失败仅记 warning 不抛异常
3. 构造：估算行写入后 → 断言 `data_adapter._read_capital_data()` 与 `advisor._build_capital_factors()` 的查询结果**不含估算行**（M-9）；若过滤后无真实行，评分输入为空/降级行为与当前 EM 失败时一致（R-5）
4. 核查估算写入为 UPDATE + INSERT OR IGNORE（三处），**全仓无估算路径的 INSERT OR REPLACE**（M-5）；估算仅写当日 1 行
5. 核查估算成功时 data_status 写 `status='estimated'`，`fetch_capital_flow` 返回 `('estimated', ...)`（M-6），019C 回退循环 `result[0]=='success'` 判定不将估算计为成功
6. 核查前置防跳过校验含 `(is_estimated = 0 OR is_estimated IS NULL)`（2.4）

### TC-019E-3 EM 覆盖重写（任务 3）
1. 构造：估算行存在 → EM 写入成功（可模拟 SQL 级）→ is_estimated 归 0、data_status 转 success
2. M-10 陷阱检查：估算写入（UPDATE 模式）**不清除占位行 ths_net_inflow**；核查三处 EM INSERT OR REPLACE 均显式携带 `is_estimated` 并赋值 0（M-7）
3. 核查不自动 force 重生成日报（E-4 裁定）——无任何对 B11 复用逻辑的改动

### TC-019E-4 前端适配（任务 4）
1. 代码核查：资金面表格 `is_estimated===1` 行追加"估算"标注（index.html 资金面表格区）；表头文案动态化（含估算时"来源：东方财富（含估算兜底数据）"）
2. 代码核查：两处采集状态三元链（status 映射）均含 `estimated → ⚠️估算` 分支，复用 `status-partial` CSS 类
3. 核查评分卡片与价格建议资金面色块**未**添加估算标注（E-6 裁定）

### TC-019E-5 评分链路全量盘点（红线 1 终审）
