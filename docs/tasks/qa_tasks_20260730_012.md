## 二、测试用例（QA可自主调整/补充）

### Q1：文件日志生成（012-A）

**验证步骤**：
1. 启动 `python app.py`
2. 触发 `GET /api/health`
3. 检查 `logs/app.log` 存在
4. 检查包含启动 banner `===== Stock Analyst 启动 PID=`
5. 检查包含 werkzeug 请求日志
6. 检查日志格式：`时间 [模块名] 级别 消息`

**通过标准**：文件存在 + banner + 请求日志 + 格式正确

### Q2：日志轮转配置（012-A）

**验证步骤**：
1. 源码审查 `app.py` main() 中 TimedRotatingFileHandler 配置
2. 确认 `when='midnight'`, `backupCount=7`, `encoding='utf-8'`
3. 确认使用 `root.addHandler()` 而非 `basicConfig()`

**通过标准**：配置参数正确 + addHandler方式

### Q3：日报进度日志（012-B）

**验证步骤**：
1. 触发 `POST /api/daily-report/generate`
2. 检查 `logs/app.log` 包含 `[日报进度]` 结构化日志
3. 确认有 `X/Y 开始 symbol name` 格式
4. 确认有 `===== 批次完成 成功X/失败Y 耗时Zs =====`

**通过标准**：进度日志存在 + 格式正确 + 有批次汇总

### Q4：进度文件（012-B）

**验证步骤**：
1. 日报生成后检查 `logs/report_progress.json` 存在
2. 确认 JSON 结构包含：date/total/current/status/started_at/finished_at
3. 确认 status="done"（生成完成后）

**通过标准**：文件存在 + JSON有效 + status=done

### Q5：单只超时机制（012-B）

**验证步骤**（源码审查 + 可选实际测试）：
1. 审查 `daily_report.py` 确认使用 `ThreadPoolExecutor` + `future.result(timeout=STOCK_TIMEOUT_SECONDS)`
2. 确认 `config.py` 中 `STOCK_TIMEOUT_SECONDS = 90`
3. 确认超时后行为：logger.error + _save_report(status='failed') + continue
4. （可选）临时设 STOCK_TIMEOUT_SECONDS=5 触发超时验证

**通过标准**：ThreadPoolExecutor 实现 + 90s配置 + 超时后skip+记录

### Q6：批次整体超时（012-B）

**验证步骤**（源码审查）：
1. 确认 `BATCH_TIMEOUT_SECONDS = 1800`
2. 确认 for 循环内有 `if time.time() - batch_start > BATCH_TIMEOUT_SECONDS: break`
3. 确认超时后有 warning 日志

**通过标准**：软超时逻辑存在 + 30min配置

### Q7：error_logs 表结构增强（012-C）

**验证步骤**：
1. 查询 `PRAGMA table_info(error_logs)`
2. 确认含 `dimension TEXT` 和 `traceback TEXT` 字段
3. 审查 `db_manager.py` 中 ALTER TABLE migration 逻辑

**通过标准**：两个新字段存在 + migration有列存在性检查

### Q8：_log_error_to_db 写入（012-C）

**验证步骤**：
1. 审查 `data_collector.py` 中 `_log_error_to_db` 函数
2. 确认内部有 try/except 保护（写DB失败不阻塞）
3. 确认 traceback 截断至 2000 字符
4. 确认 `collect_stock_data` 中 6 个维度的 except 块均调用了此函数
5. （可选）触发一个会失败的采集，查询 error_logs 最新记录

**通过标准**：函数存在 + 保护逻辑 + 6维度接入

### Q9：failure_summary（012-C）

**验证步骤**：
1. 审查 `daily_report.py` 中 failure_summary 聚合逻辑
2. 触发日报生成（全部成功时 failure_summary=None）
3. 确认 API 返回的 JSON 中包含 `failure_summary` 字段

**通过标准**：字段存在 + 全成功时为None + 有失败时含 by_reason

### Q10：011增量逻辑回归（红线）
