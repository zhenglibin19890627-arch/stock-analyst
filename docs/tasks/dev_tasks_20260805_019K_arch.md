## 一、需求背景

### 1.1 缺陷描述（2026-08-05 实证）

东方财富资金流接口当日全部 RemoteDisconnected（push2his/push2/akshare 三层全失败）。报告批次资金面补采 23 只仅 7 只成功，连续失败 5 次熔断，剩余股票无真实资金数据 → 评分资金面因子缺失，靠估算兜底（仅展示不参与评分）。

**同日 THS 批量预取成功获取 5199 只真实资金流数据（45s 完成）**，但仅写入辅助字段 `ths_net_inflow`，未顶替 `main_net_inflow`——真实数据闲置，评分链路读不到。

### 1.2 监理裁定（方案一）

东财三层全失败时，用同花顺当日真实资金数据顶替写入 `main_net_inflow`，使资金面因子仍可用真实数据参与评分。

### 1.4 核心矛盾（PM 提请重点关注）

**THS 主接口"净额"口径 = 全部资金净流入（总主动买入-总主动卖出），非主力净流入**（data_collector.py L1369 docstring 明确）；而 `main_net_inflow` 字段语义为**主力净流入**（东财口径）。两者口径不同。

但 THS **备选接口** `stock_individual_fund_flow_rank(indicator='今日')` 含"**今日主力净流入-净额**"列（L1221 列映射），口径与东财主力一致。

→ 顶替数据源选哪个、是否接受口径偏差，是本批次第一决策点。

## 二、评审决策点（请逐项裁定）

### D-1：顶替数据源与口径（核心）

**背景**：THS 主接口"净额"=全部资金净流入（非主力）；备选接口"今日主力净流入-净额"=主力口径。今日批次 20:11 日志显示 THS 主接口成功（5199 只），备选接口未持久化。

**架构师请核验**：
- Read L1366-1474（批量写入仅 ths_net_inflow）+ L1196-1235（两接口列结构）
- 裁定：顶替写入 main_net_inflow 用哪个源？
  - 甲：复用批量预取已入库的 `ths_net_inflow`（主接口口径，零额外请求，但口径=全部资金非主力）
  - 乙：EM 失败时实时调 THS 备选接口取"今日主力净流入-净额"（口径匹配主力，但 EM 失败时多一次 THS 网络请求；THS 超时已有 019I 保护）
  - 丙：其他
- 若选甲：口径偏差（全部资金 vs 主力）对评分因子影响多大？是否可接受（advisor L1111-1157 各因子用 main_net_inflow 的方式）？
- 若选乙：备选接口是否必然可用（今日主接口成功时备选接口行为）？是否需要缓存备选结果？

**裁定**：甲 / 乙 / 丙 + 理由

### D-2：is_estimated 标记语义

**背景**：019E 建立"is_estimated=1 估算行不参与评分"机制（advisor L1124 过滤）。THS 是真实数据（非估算公式），顶替行应标记为？

**架构师请核验**：
- THS 数据顶替后写 is_estimated=0（进入评分）→ 评分因子使用 THS 口径数据，是否污染评分纯净性（019E 建立的"评分仅用真实数据"语义）
- 写 is_estimated=1（不进评分）→ 顶替仅展示，资金面因子仍缺失——方案一目标落空
- 是否有第三方案：新增来源标记（如 ths 列已存在，或 data_status message 标注来源），is_estimated=0 但可追溯来源

**裁定**：is_estimated=0（参与评分）/ =1（仅展示）/ 其他 + 理由

### D-3：历史连续性（5日均/连续性因子混用）

**背景**：THS 仅当日 1 行（无历史）。顶替当日行后，`main_avg_5d`（L1141-1145）与 `consecutive`（L1147-1157）将混用 THS 当日 + 东财历史前 4 日数据。

**架构师请核验**：
- 若 D-1 选甲（全部资金口径）：混用口径对 5 日均/连续性的影响（可接受 / 需标注 / 需排除）
- 若 D-1 选乙（主力口径）：口径一致时混用是否可接受
- 是否有必要限制：仅当该股无任何 EM 历史时才顶替？还是无条件顶替当日？

**裁定**：无条件顶替 / 条件顶替 + 条件定义 + 理由

### D-4：写入时机与位置

**背景**：候选插入点 ① `fetch_capital_flow()` L2123 `em_all_failed` 处（EM 失败后、估算兜底前，从库读 ths_net_inflow 或调 THS 备选）；② THS 批量写入时（L1449-1467）同步写 main_net_inflow（无 EM 判定，正常路径也写）。

**架构师请核验**：
- ① 与 ② 的优劣：② 会绕过"EM 失败才顶替"约束，正常路径也写入 THS 口径 → 可能覆盖/抢先于 EM 真实数据（防覆盖风险）；① 只在 EM 失败路径触发，与估算兜底同级
- ② 是否违反 019E"主力净流入唯一来源为东财"裁定（L1371 docstring）？是否需同步修订该注释
- ② 路径下 019E 补采触发（L1476-1524）仍会调 EM 补采，补采成功后覆盖 THS → 链路是否闭环

**裁定**：插入点① / ② / 其他 + 理由

### D-5：防覆盖机制

**背景**：现有防覆盖（L1953-1960）检查 `data_status.message.startswith('东方财富')`。顶替值写入后 message 开头不同，防覆盖保护范围需明确。

**架构师请核验**：
- THS 顶替写入的 data_status message 建议格式（如"同花顺顶替(...)"）
- 三种覆盖关系须明确：EM 真实 → 覆盖 THS 顶替（必须允许，EM 恢复后回补）；估算 → 不得覆盖 THS 顶替（is_estimated 判定已隔离）；THS 顶替 → 不得覆盖 EM 真实（正常路径不触发顶替，D-4 裁定后闭环）
- 019E M-7（EM 写入 is_estimated=0 防御估算→真实覆盖）是否需扩展到 THS 路径

**裁定**：覆盖关系表确认 + 需补充防护 + 理由

### D-6：港股范围

**背景**：THS 批量源仅 A 股（fetch_capital_flow_batch 入参 a_stock_symbols，L476 daily_report 过滤 market=='a_stock'）。港股东财失败时无 THS 可顶替。
