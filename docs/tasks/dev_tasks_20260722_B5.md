## 技术方案（产品经理指定）

### 设计原则

| 原则 | 说明 |
|---|---|
| **规则化（非ML）** | 用可解释的 if-else 规则调参，用户能看懂为什么调 |
| **渐进调整** | 每次调整幅度不超过 +/-5%，避免剧烈波动 |
| **可追溯** | 每次优化记录到 strategy_params 表，用户可查看历史 |
| **全自动** | 每周自动执行，无需用户干预（2.9.2） |
| **A/H独立** | A股和港股分别优化（2.9.1） |

### 优化引擎架构

```
modules/optimizer_engine.py (~300行)

class OptimizerEngine:
    def run_weekly_optimization(market) -> dict:
        \"\"\"每周自动优化主入口\"\"\"
        1. 读取 backtest_results（含模拟数据）
        2. 计算各维度准确率贡献
        3. 计算各评级档位准确率
        4. 生成权重调整建议
        5. 生成阈值调整建议
        6. 写入 config_weights.json（热加载生效）
        7. 记录到 strategy_params（审计追溯）
        返回 {adjusted, changes, reason}

    def analyze_dimension_accuracy(market) -> dict:
        \"\"\"分析各维度对总准确率的贡献\"\"\"

    def suggest_weight_adjustment(market) -> dict:
        \"\"\"基于准确率生成权重调整建议（渐进 +/-5%）\"\"\"

    def suggest_threshold_adjustment(market) -> dict:
        \"\"\"基于评级分布生成阈值调整建议\"\"\"

    def get_optimization_history(market) -> list:
        \"\"\"查看历史优化记录（US-10）\"\"\"
```

### 优化规则（核心逻辑）

#### 规则1：权重调整

```
对每个维度 dim:
  dim_accuracy = 该维度得分与评级正确性的相关系数
  if dim_accuracy > 整体准确率 + 10%:
      建议权重 += 5%（上限 50%）
  elif dim_accuracy < 整体准确率 - 10%:
      建议权重 -= 5%（下限 5%）
  归一化使总和 = 1.0
```

#### 规则2：阈值调整

```
对每个评级档位:
  actual_correct_rate = 该档位回测准确率
  if actual_correct_rate < 40% 且 样本 >= 20:
      建议收窄该档位范围（边界内缩 2 分）
  elif actual_correct_rate > 75% 且 样本 >= 20:
      建议扩大该档位范围（边界外扩 2 分）
  边界约束：不低于 0/30/50/70/85 基准 +/- 5 分
```

#### 规则3：安全阈值

```
- 单次调整幅度：权重 +/-5%，阈值 +/-2分
- 最低样本量：>=50 条回测才触发优化
- 连续2次同方向调整需间隔 >=7天
- 优化后自动回测验证：新参数准确率不低于旧参数
```

## 开发方执行要求

1. **规则化可解释**：每次调整必须附带 reason 字段（如"kline准确率72%高于均值58%，权重+5%"）
2. **安全阀必须实现**：优化后回测准确率不得低于优化前（否则回滚）
3. **渐进调整**：严禁一次性大幅调整（权重单次<=5%，阈值单次<=2分）
4. **验收留痕**：完成后在 reports/ 生成自验报告
5. **回归范围**：现有评分/回测/导出功能不受影响
