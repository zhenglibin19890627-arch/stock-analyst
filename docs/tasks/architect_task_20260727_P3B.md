## 你需要评审的 5 个技术决策点（D1-D5）

请逐项给出评审结论（✅同意PM倾向 / ⚠️调整建议 / ❌反对并给替代方案），并说明理由。

### D1：扫描挂载方式
- **PM倾向**：复用 `daily_report.py` 的 `_scheduler_tick`，日报生成完成后调用 `alert_engine.scan_once()`
- **你需要评审**：
  1. 是否需要独立定时器（而非复用日报调度）？
  2. 异常隔离是否充分（扫描失败不能阻塞日报）？
  3. 幂等性设计（同一天重复扫描是否产生重复 alert_history）？

### D2：表结构设计
- **PM倾向**：新建 `alert_rules`（规则配置）+ `alert_history`（触发历史，含 is_read 字段）两表
- **你需要评审**：
  1. is_read 放 history 表 vs 拆 alert_read_state 独立表，哪种更合理？
  2. 索引设计（alert_history 按 stock_id / triggered_at 查询高频）
  3. 外键约束（alert_history.rule_id 是否强制关联 alert_rules）
  4. 请给出**完整的 CREATE TABLE 语句草案**

### D3："连续净流出"算法
- **PM倾向**：取 raw_capital_flow 最近 N 天（默认3）的 main_net_inflow，全为负则触发
- **你需要评审**：
  1. 缺失数据天数如何处理（计入中断 vs 跳过）？
  2. N天窗口的边界（含今天 vs 不含今天）
  3. 港股无两融数据、A股部分股票 main_net_inflow 缺失时的降级策略
  4. 给出**核心判定伪代码**

### D4：评级跨档判定
- **PM倾向**：对比 latest ratings_history.rating 与同 stock_id 上一条记录的 rating，不同即触发
- **你需要评审**：
  1. 跨档判定是相邻两次对比，还是与指定基准日对比？
  2. 首次评级（无历史记录）如何处理？
  3. rating 字段是中文文本（"推荐买入"/"持有观望"等），如何定义"档位顺序"做升降级判定？
  4. 给出**核心判定伪代码**

### D5：规则配置存储
- **PM倾向**：新建 alert_rules 独立表（职责清晰）
- **你需要评审**：
  1. 是否复用现有 strategy_params 表（已有 market/param_type/param_key 结构）？
  2. 配置热加载机制（修改规则后是否需重启服务）？
  3. 给出**推荐方案与理由**
