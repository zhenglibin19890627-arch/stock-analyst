## 二、背景与问题

监理 2026-08-09（周日，非交易日）发现：总览看板上只有宁德时代、中国中免 2 只股票有评分，其余 27 只"消失"。

PM 只读核查确认根因（非数据丢失）：

1. 看板接口 `/api/portfolio/watchlist-scores`（`app.py` L1860-1891，P2 批次实现）先取**全局** `MAX(report_date)`，再把全部自选股 JOIN 到该**单一日期**。
2. 当日数据库：08-09 仅有 3 份报告（宁德时代 11:53 测试生成、中国中免 17:38 个股触发、恒瑞医药 18:00 个股触发）；其余 26 只的最新报告日期为 08-07（29 份齐全）。
3. 于是全局最新日期 = 08-09，其余 26 只在该日期 JOIN 不到报告 → 看板显示为空。
4. `/api/portfolio/summary`（`app.py` L1780-1836）的均分/评级分布同样按"全局单一最新日期"聚合，存在同口径问题（当前只会统计到 3 份报告）。

**本质**：看板口径是"最新一个报告日期当天的报告"，而非"每只股票各自最新的一份报告"。交易日全员出报告时二者等价，非交易日（或部分股票当日无报告时）即出现空窗。

## 三、需求描述（PM 澄清后口径）

**核心口径（监理已指明）**：看板显示**每只股票最近一份有效报告**的评分与评级，并**标注该报告的日期**，使用户能分辨"这是哪天的评分"。

细化规则：

1. "最近一份有效报告"定义：该股票 `status='ok'` 的报告中 `report_date` 最大的一份；`report_type` 的取舍（daily/intraday）沿用 019D 的 **daily 优先 + status='ok'** 原则，但判定粒度由"按日全局"细化为"按股按日"：**每股在自身最新 report_date 上 daily 优先；全库同日时与 019D 全局判定完全等价**（评审裁定；`_resolve_report_type` 本身保留，继续服务单日期场景，本需求不再调用它）。
2. 前端表格每只股票需可见其报告日期（列或角标均可，样式由开发按现有风格实现）。
3. **交易日行为不变**：当全部股票报告同日时，看板呈现与现状一致（评分、排序、涨跌标注不回归）。
4. **汇总卡片口径同步**（P1 子任务）：`/api/portfolio/summary` 的均分、评级分布改为与看板同口径（每股最新一份），并显示数据日期范围（如"2026-08-07 ~ 2026-08-09"或单一日期），避免看板显示 29 只而均分只按 3 只算的自相矛盾。
5. 若某股票完全无报告（新股/从未生成），维持现状展示（无评分、排末尾），报告日期显示为空或"暂无"。
6. **标签修正（监理裁定，2026-08-09）**：多日期混排时，前端"较昨日"标签改为"**较上期**"（08-07 行的 score_change 实际是相对 08-06 的变化，改后语义准确）。

## 四、范围提示（供架构师评审参考，不构成设计结论）

- 后端：`app.py` 的 `api_portfolio_watchlist_scores`、`api_portfolio_summary` 两个接口的 SQL/聚合逻辑。**返回结构改造方向（评审裁定）**：顶层**保留** `report_date` 单值字段（语义延续为"入选报告的最新日期"，向后兼容），**新增** `report_date_min`（入选报告最早日期）；每行股票字典**新增行级 `report_date`**（该股最新有效报告日期，无报告为 null）。两接口必须共用同一"每股最新一份"SQL 片段（评审建议新增 `_latest_report_join_sql()` 辅助，杜绝两处口径漂移）。
- 前端：`templates/index.html` 总览看板表格渲染处（`loadRatings` / 看板渲染函数，L1117、L4732 附近），增加报告日期展示。
- 性能与缓存：现有 ETag 机制需保持有效（注意 report_date 参与 payload 后 304 语义不变坏）。
- **红线**：只改读路径与展示层；不得写生产库、不得改动评分引擎（daily_report.py 评分逻辑）、不得改动 019Q 补采链路。

## 五、验收标准（QA 依据）

1. **当前生产库即天然测试现场**（非交易日、部分股票当日有报告）：看板应显示**全部非退市自选股（不硬编码股数，以 stocks 表非退市为准）**。**动态断言**（不写死股数与日期分布——评审指出非交易日浏览个股详情会触发 B11 实时分析，报告数在动态增长）：每行标注的报告日期 = 该股 daily_reports 中最新一份 status='ok' 报告的日期；QA 验收前后各查一次库对比。
2. 每行评分/评级与该股票 daily_reports 中对应日期记录一致（抽查 ≥5 只，含宁德时代、中国中免、任意 08-07 股票）。
3. 汇总卡片均分/评级分布与看板同口径自洽，且展示数据日期范围。
4. 交易日回归：以 08-07 数据验证（前提：08-07 全 29 份同日且全部为 daily，与旧口径完全等价）、排序、涨跌标注、无日期混乱。**补充断言**：每股最新日期上 daily 与 intraday 并存时取 daily（08-06、07-31 两日每股确有 daily+intraday 双行，为现成验证数据）。
5. 无报告股票正确兜底（可临时用只读查询构造断言，不得为测试写生产库）。
6. QA 验收全程对生产库零写入（只读连接或 `file:...?mode=ro`）。
