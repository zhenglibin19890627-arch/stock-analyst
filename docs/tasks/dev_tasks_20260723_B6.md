## 任务卡 1：M9-COOLDOWN 冷却期执行逻辑

| 字段 | 内容 |
|---|---|
| **任务ID** | M9-COOLDOWN |
| **优先级** | P1 |
| **需求映射** | B5 任务书规则3"连续2次同方向调整需间隔>=7天" |
| **缺陷描述** | `MIN_INTERVAL_DAYS=7`（L44）已定义，`run_weekly_optimization()` docstring 步骤2 提及冷却期检查，但**实际代码无任何检查逻辑**。手动触发 `POST /api/optimizer/run` 可无限频繁执行，违反安全约束 |
| **核心动作** | 在 `run_weekly_optimization()` 中实现冷却期检查，阻止 7 天内同方向重复调整 |

### 技术方案

#### 实现要点

| # | 要点 | 说明 |
|---|---|---|
| 1 | 新增 `_get_last_optimization(market)` | 从 strategy_params 查询最近一条 optimization_log，解析 timestamp + changes 中的调整方向 |
| 2 | 新增 `_is_same_direction(last_log, current_suggestion)` | 比较上次权重调整方向（增/减）与本次建议方向是否一致。判断维度：各维度权重 delta 符号相同即为同方向 |
| 3 | 方向预判 | 冷却期检查需在生成权重建议之后执行（需先知道本次方向），因此调整代码顺序：先 `suggest_weight_adjustment()`，再检查冷却期，再写入 |
| 4 | 仅约束同方向 | 反向调整不受冷却期限制（如上次增权，本次降权可立即执行） |
| 5 | 定时调度自然满足 | 每周日执行一次，间隔=7天，自然满足。此检查主要防御手动触发场景 |
| 6 | 返回值增加 `cooldown_remaining` 字段 | 便于 UI/API 展示剩余冷却天数 |

#### 主流程调整（run_weekly_optimization 步骤重排）

```
原流程：1.样本量 → 2.准确率 → 3.维度分析 → 4.权重建议 → 5.阈值建议 → 6.写入 → ...
新流程：1.样本量 → 2.准确率 → 3.维度分析 → 4.权重建议 → 4.5.冷却期检查 → 5.阈值建议 → 6.写入 → ...
```

冷却期检查伪代码：
```python
# 步骤 4.5：冷却期检查（在生成权重建议之后）
if weight_suggestion['should_adjust']:
    last_opt = self._get_last_optimization(market)
    if last_opt:
        days_since = (now - last_opt['time']).days
        if days_since < MIN_INTERVAL_DAYS:
            if self._is_same_direction(last_opt['direction'], weight_suggestion['delta']):
                return {
                    'adjusted': False,
                    'changes': [],
                    'reason': f'冷却期未满（距上次同方向调整仅{days_since}天<{MIN_INTERVAL_DAYS}天），跳过',
                    'market': market,
                    'cooldown_remaining': MIN_INTERVAL_DAYS - days_since,
                }
```

### 技术方案

#### 新增方法 `_write_thresholds(market, adjustments)`

```python
def _write_thresholds(self, market, adjustments):
    """将阈值调整写入 config_weights.json 的 rating_mapping
    
    规则：
    - narrow（收窄）：该档位 min += shift, max -= shift（范围缩小）
    - expand（扩大）：该档位 min -= shift, max += shift（范围扩大）
    - 边界约束：调整后不得偏离 THRESHOLD_BASELINES +/- THRESHOLD_MAX_DEVIATION(5分)
    - 相邻档位不得重叠（如"推荐买入"min 不得 <= "持有观望"max）
    """
```

#### 阈值调整计算规则

```
对每个 adjustment:
  rating = adjustment['rating']           # 如 "推荐买入"
  action = adjustment['action']           # "narrow" 或 "expand"
  shift  = adjustment['suggested_shift']  # 固定为 MAX_THRESHOLD_STEP=2

  current = rating_mapping[rating]        # 如 {min:70, max:84}
  baseline = THRESHOLD_BASELINES[rating]  # 如 70

  if action == 'narrow':
      new_min = current['min'] + shift
      new_max = current['max'] - shift
  elif action == 'expand':
      new_min = current['min'] - shift
      new_max = current['max'] + shift

  # 边界约束（不可偏离基准超过5分）
  new_min = max(baseline - THRESHOLD_MAX_DEVIATION, new_min)
  new_max = min(100, new_max)  # 最高档上限100
  # 最低档下限0
  if rating == '强烈建议卖出': new_min = 0

  # 相邻档位不重叠校验
  if 与相邻档位产生重叠 → 跳过该档位调整，reason 中说明
```

#### 安全阀（阈值专用）

```python
def _validate_threshold_safety(self, market, old_mapping, new_mapping):
    """安全阀：新阈值下回测准确率不得低于旧阈值
    
    实现：用新旧 rating_mapping 分别对 backtest_results 中的 total_score 重新映射评级，
    对比 is_correct 命中率
    """
    old_acc = self._calc_accuracy_with_mapping(market, old_mapping)
    new_acc = self._calc_accuracy_with_mapping(market, new_mapping)
    return new_acc >= old_acc - 0.01  # 允许1%误差
```

#### 新增辅助方法清单

| 方法 | 用途 |
|---|---|
| `_write_thresholds(market, adjustments)` | 写入 rating_mapping 到 config_weights.json |
| `_validate_threshold_safety(market, old, new)` | 安全阀：新旧阈值准确率对比 |
| `_calc_accuracy_with_mapping(market, mapping)` | 用指定 rating_mapping 重新计算回测准确率 |
| `_check_overlap(new_mapping)` | 相邻档位不重叠校验，返回是否合法 |
| `_get_last_optimization(market)` | 查询最近优化记录（冷却期用） |
| `_is_same_direction(last_direction, current_delta)` | 判断调整方向是否一致 |

#### 主流程修改（run_weekly_optimization 步骤8扩展）

```
现有步骤 8（安全阀）扩展为：
  8a. 权重安全阀（已有，不变）
  8b. 阈值安全阀（新增）：
      - 保存 old_mapping
      - 调用 _write_thresholds() 写入新阈值
      - 调用 _validate_threshold_safety() 验证
      - 不通过 → 回滚阈值（恢复 old_mapping）
      - 阈值回滚不影响权重调整（两者独立验证）
```
