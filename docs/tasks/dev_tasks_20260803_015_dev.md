## 三、需求项（7项，按风险由低到高排序）

### U1（#9）持仓成本小数位规整　【风险：极低】
**问题**：持仓管理页成本价显示如 `60.784`（3位小数），普通用户不直观。
**位置**：`templates/index.html` 约 L2796 `var costDisplay = (h.cost_price || 0) + adjustedTag;`
**要求**：持仓页成本价统一显示 **2位小数**（注意保留 `adjustedTag`「已修正」标签拼接）。
**验收**：持仓页所有成本价显示为2位小数，「已修正」标签仍正常显示。
**注意**：自选股页（L1891-1893）已用 `.toFixed(2)`，**本次只需修持仓页**，不要动自选股页。

### U2（#6）今日报告 / 盘中快报 功能说明　【风险：极低】
**问题**：用户分不清「今日报告」和「盘中快报」的区别。
**位置**：`templates/index.html` 约 L1121-L1123 三个按钮区域。
**要求**：在按钮下方添加简明说明文字，向零代码用户解释两者区别。建议文案（可优化）：
- 「🚀 生成今日报告」= 盘后汇总，生成当日完整分析报告（含评分变动、降级提示）
- 「📊 盘中快报」= 盘中实时刷新评分，快速查看当日盘中变化（不覆盖盘后日报）
**验收**：按钮区域有清晰说明，零代码用户能理解两者区别，且不破坏现有按钮功能与布局。

### U3（#10）回测中心一句话总结　【风险：低】
**问题**：回测页信息密度过高，普通股民一眼看不过来。
**位置**：`templates/index.html` 回测视图（约 L1145+），数据由 `loadBacktestMarketReport()`（约 L5162+）渲染。
**要求**：回测页顶部数据加载后，增加一行「一句话总结」摘要，例如：「系统 T+1日准确率 60%，推荐买入评级命中率最高」。需从回测返回数据中动态提取关键指标（总体准确率、最强评级档位）。
**验收**：回测页顶部显示一句话总结，数值随实际数据动态变化；现有回测表格/图表不受影响。

### U4（#4）专业术语悬浮解释　【风险：低】
**问题**：PE、ROE、主力净占比、RSI 等专业术语无解释。
**位置**：个股详情页（`viewReport`/`showReport` 渲染区域），各维度指标展示处。
**要求**：为关键专业指标添加鼠标悬浮解释（HTML `title` 属性 或 自定义 tooltip）。至少覆盖以下术语：
- 技术面：RSI、MA（均线）、布林带
- 基本面：PE（市盈率）、PB（市净率）、ROE（净资产收益率）、营收增长率
- 资金面：主力净流入、主力净占比、融资余额
- 消息面：情绪分析（正面/负面/中性）
解释文案需**通俗易懂**（如「PE=市盈率，股价 ÷ 每股收益，一般越低越便宜，但需结合行业判断」）。
**验收**：个股详情页关键指标悬浮可见通俗解释；不得改变数值显示与页面布局。

### U5（#7）预警功能入口显化　【风险：中】
**问题**：铃铛图标入口隐蔽，且**无法设置预警规则**。
**位置**：`templates/index.html` 铃铛按钮（约 L968 `#alertBellBtn`）、`toggleAlertDropdown` 及预警下拉面板（CSS 约 L434+）。
**要求**：
1. 在预警下拉面板内（或导航栏）增加「➕ 添加预警规则」入口。
2. 实现「添加规则」弹窗/表单，调用 **现有 P3-B 预警 API**（开发前先核查 `/api/alerts/rules` 等已有接口，**禁止新建后端路由**）。
3. 支持「查看已有规则列表」。
**验收**：用户可通过 UI 添加、查看预警规则（调用现有 API 成功）；铃铛入口可见性提升；不破坏现有预警通知、已读、徽标功能。
**注意**：本项**只对接现有 API，不新增/修改后端路由**。若发现现有 API 不足以支撑 UI，**停止并向 PM 反馈**，不要自行新增路由。

### U6（#3）自选股按钮精简与操作引导　【风险：中】
**问题**：自选股每行 8 个操作按钮太密集，新手不知从何下手。
**位置**：`templates/index.html` 自选股行渲染（约 L1924-L1931），8 个按钮：编辑/采集数据/四维分析/生成评级/查看报告/查看数据/加入持仓/删除。
**要求**：
1. 将「采集数据 → 四维分析 → 生成评级」三步合并为一个**「⚡ 一键分析」按钮**（内部依次调用 collectData → analyzeStock → generateAdvice，保持原函数与原 API 不变）。
2. 其余按钮（查看报告/查看数据/加入持仓/编辑/删除）收进「⋯ 更多」下拉，或保留高频按钮（查看报告）+ 更多。
3. 顶部「⚡ 批量分析+评级」按钮（L1050）保留不变。
4. 添加**首次操作引导**：当某股票无任何数据时，提示「首次使用请先点『⚡ 一键分析』采集并分析数据」。
**验收**：
- 自选股每行按钮精简（≤4个可见按钮 + 「更多」）；
- 「一键分析」能依次完成采集→分析→评级三步，结果与原分步操作一致；
- 原有的编辑/删除/加入持仓/查看报告/查看数据功能**全部可在「更多」中访问，无功能丢失**；
- 批量分析按钮不受影响。

### U7（#5）数据完整度显示口径统一　【风险：中，涉及 app.py】
**问题**：个股详情页「顶部显示全部100%」，但「详情区显示 基本89% 资金67% 消息80%」，同一页面口径矛盾，用户困惑。
**根因（PM已溯源）**：`app.py` 约 L996-L1017 的 data_quality 推导逻辑——当某维度 `key_factors[dim].top_factors` 中**没有 `data_completeness` 字段**时，默认填 `1.0`（即100%），与该维度实际数据完整度不符。前端 `templates/index.html` 约 L4056-L4078 直接展示这些百分比。
**要求**：
1. **修复默认值逻辑**：当无法从 `top_factors.data_completeness` 解析到完整度时，**不应默认为 100%**，应标记为「未知/未统计」或根据该维度是否有实际数据给出更合理的值（如：维度有数据→视为完整，但显示「已采集」而非「100%」；无数据→0%）。
2. **统一前端口径**：确保「顶部汇总」与「分维度明细」展示的完整度含义一致、数值不矛盾。若顶部是聚合值，需与分维度值在数学上一致（如顶部=四维度平均，或顶部直接展示分维度而非单一100%）。
3. **红线提醒**：此修改在 `app.py` L996-L1017 范围内，**属本批次唯一允许的 app.py 改动点**；改动后不得影响 `/api/report-latest` 返回的其他字段。
**验收**：同一股票详情页，完整度显示**口径一致、数值不矛盾**；当某维度缺 data_completeness 时不再误显100%；其余字段（评分/评级/雷达图/价格建议）不受影响。
