## 一、需求背景

005 价格建议已上线，输出结构化价格建议：
- **无持仓**：买入区间（buy_range_low/high）、目标价（target_price）、止损价（stop_loss）
- **有持仓**：止盈价（take_profit）、止损价（stop_loss）

需要设计**回测验证方案**，回答核心问题：**价格建议的命中率如何？算法参数是否需要微调？**

## 二、价格建议算法参数（005已实现，待验证）

### 无持仓模式
| 建议项 | 算法 | 参数 |
|---|---|---|
| 买入中枢 | MA20（可用）否则 close | — |
| 买入下限 | 中枢 - ATR×0.5 | ATR系数=0.5 |
| 买入上限 | 中枢 + ATR×0.3 | ATR系数=0.3 |
| 目标价 | max(boll_upper, ma60)，不低于 close×1.05 | 最低5%空间 |
| 止损价 | 买入下限 - ATR×1.0 | ATR系数=1.0 |

### 有持仓模式
| 建议项 | 算法 | 参数 |
|---|---|---|
| 止盈价 | cost × (1 + 目标涨幅%) | 评级映射：推荐买入→+20% |
| 止损价 | cost × (1 - 止损比例%) | 评级映射：推荐买入→-7% |

## 四、设计决策点

### 决策点1：命中率定义（核心）

需定义"价格建议命中"的标准：

| 建议项 | 候选定义 | 说明 |
|---|---|---|
| 买入区间命中 | T+N 内最低价 ≤ 买入上限 且 T+N 收盘价 ≥ 买入下限 | 价格曾进入买入区间 |
| 目标价命中 | T+N 内最高价 ≥ 目标价 | 价格曾达到目标 |
| 止损价命中 | T+N 内最低价 ≤ 止损价 | 价格曾跌破止损 |
| 止盈价命中（持仓） | T+N 内最高价 ≥ 止盈价 | 价格曾达到止盈位 |

> 需方案设计师明确：用哪段时间窗口（T+5？T+20？）、是否需要日内 high/low（raw_kline 有此字段）。

### 决策点2：回测方法

| 方法 | 说明 | 数据依赖 |
|---|---|---|
| A. 复用 backtest_results | 对已有478条记录，在评级日模拟生成 price_advice，然后验证 T+N 命中率 | 需在评级日点回算 ATR/MA/BOLL |
| B. 新建独立回测 | 仿照 run_historical_simulation，遍历历史K线，每5天生成 price_advice，验证命中率 | 需写新回测函数 |

> 需方案设计师推荐哪种方法，以及是否需要新建 DB 表存储结果。

### 决策点3：验证周期

| 周期 | 说明 |
|---|---|
| T+5（1周） | 短期命中率 |
| T+20（1月） | 中期命中率 |
| 两者都要 | 对比短期 vs 中期 |

### 决策点4：输出指标

需定义回测报告应包含哪些指标：
- 各建议项的命中率（百分比）
- 平均达到天数（价格达到目标用了几天）
- 未命中案例的平均偏差（目标价 - 实际最高价）
- 分评级统计（推荐买入的命中率 vs 持有观望）
- A股 vs 港股对比

### 决策点5：参数微调建议

基于回测结果，是否需要建议微调算法参数：
- ATR 系数（买入区间 0.5/0.3，止损 1.0）
- 目标涨幅映射（推荐买入 +20%）
- 止损比例映射（推荐买入 -7%）

### 决策点6：实现复杂度评估

- 是否需要新建模块（如 `price_backtest.py`）？
- 是否需要新增 API 端点？
- 是否需要新增 DB 表？
- 前端是否需要展示回测结果？
