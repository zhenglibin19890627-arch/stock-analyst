## 一、PM 根因调查结论

PM 已实际执行 SQL/Python 核验（非仅凭开发自验），确认以下 **5 个根因**：

### 根因 1（P0-CRITICAL）：ratings_history 无 UNIQUE 约束 → 重复记录膨胀回测样本

**证据：**
- `ratings_history` 表无 `UNIQUE(stock_id, rating_date)` 约束
- `_save_rating()` 使用 `INSERT OR REPLACE`，但无 UNIQUE 约束时退化为纯 INSERT
- 600276（恒瑞医药）在 2026-07-16 有 **32 条**重复记录
- 600276 在 2026-07-18 有 **35 条**重复记录
- 22 条"推荐买入"回测记录实际仅来自 **7 个唯一 (stock_id, rating_date)** 组合
- 回测准确率被重复样本严重扭曲

### 根因 2（P0-CRITICAL）：price_at_rating 与 K 线收盘价不匹配

**证据：**
- 600276 在 07-16 的 K 线收盘价 = **55.99**
- 但早期 ratings_history 记录的 price_at_rating = **56.85**（不匹配任何 K 线收盘价！）
- 原因：`_read_latest_close()` 读取分析运行时的最新 K 线，若分析在当日 K 线采集前运行，price_at_rating 为前一日或盘中价格
- 后期记录（rh_id≥67）的 price_at_rating = 55.99（K 线采集后重新分析）
- 错误的 price_at_rating 导致收益率计算偏差（-6.44% vs 正确的 -5.0%）

### 根因 3（P1-HIGH）：score_date 使用 datetime.now() 而非 K 线 trade_date

**证据：**
- `scoring_engine.py` L1067-1068：`score_date = datetime.now(_CN_TZ).strftime('%Y-%m-%d')[:10]`
- 实际数据：rating_date=2026-07-25（周六），kline_date=2026-07-24（周五）
- 回测 `_get_tn_price()` 使用 `trade_date > rating_date` 查找 T+N 价格
- 非交易日运行时，rating_date 晚于实际数据日期，T+N 查找偏移

### 根因 4（P1-HIGH）：normalize_rating 对旧格式 D 评级 + 高分数的错误映射

**证据：**
- rh_id=33：rating=**D**，total_score=**74.8**
- `normalize_rating('D', 74.8)` → `_map_rating(74.8)` → **"推荐买入"**
- 但 D 评级的正确映射应为 **"强烈建议卖出"**（RATING_LEGACY_MAP）
- 旧引擎存在 rating 与 total_score 不一致的 bug，normalize_rating 优先使用 score 导致错误放大

### 根因 5（P2-MEDIUM）：模拟回测仅用技术面单维度映射评级

**证据：**
- `run_historical_simulation()` 用 `_calc_technical_score_from_kline()` 计算技术面得分
- 技术面得分 ≥70 直接映射为"推荐买入"
- 但真实系统为四维加权（A股技术面仅占 26.3%），技术面 70 分 ≠ 总分 70 分
- 模拟"推荐买入"准确率也仅 43.3%（T+1 avg=-1.44%），技术指标滞后性导致买入信号出现在局部高点

### 数据全景（PM 核验）

| 评级 | 真实回测 total | correct | wrong | neutral | accuracy |
|---|---|---|---|---|---|
| 推荐买入 | 22 | 0 | 21 | 1 | **0.0%** |
| 建议减仓 | 275 | 65 | 75 | 135 | 46.4% |
| 持有观望 | 499 | 235 | 165 | 99 | 58.8% |
| 强烈建议卖出 | 6 | 0 | 0 | 6 | N/A |

"推荐买入" T+1 收益率：n=22, avg=**-4.96%**, min=-9.84%, max=-0.23%（**全部为负**）

## 二、任务卡

### T1：ratings_history 去重 + UNIQUE 约束（P0）

**目标：** 消除重复记录，防止未来重复写入

**修改文件：**
- `database/db_manager.py`：建表语句添加 `UNIQUE(stock_id, rating_date)`
- `modules/advisor.py`：`_save_rating()` 确认 `INSERT OR REPLACE` 在有 UNIQUE 约束后正确工作

**技术方案：**
1. 在 `db_manager.py` 的 `ratings_history` 建表 DDL 中添加 `UNIQUE(stock_id, rating_date)`
2. 编写迁移逻辑：对已有数据库，创建唯一索引（`CREATE UNIQUE INDEX IF NOT EXISTS idx_ratings_unique ON ratings_history(stock_id, rating_date)`）
3. 迁移前先清理重复数据：每组 (stock_id, rating_date) 仅保留 **id 最大** 的记录（最新分析结果）
4. 验证 `INSERT OR REPLACE` 在 UNIQUE 约束下正确执行 UPSERT

**验收标准：**
- [ ] `PRAGMA index_list(ratings_history)` 显示唯一索引存在
- [ ] `SELECT stock_id, rating_date, COUNT(*) FROM ratings_history GROUP BY stock_id, rating_date HAVING COUNT(*)>1` 返回 0 行
- [ ] 对同一 stock_id+rating_date 连续调用 2 次 `_save_rating()`，ratings_history 仅 1 条记录
- [ ] 已有数据中 600276 在 07-16 的记录从 32 条降为 1 条

### T2：修复 price_at_rating 来源（P0）

**目标：** price_at_rating 必须为 rating_date 对应交易日的 K 线收盘价

**修改文件：**
- `modules/advisor.py`：`_save_rating()` 和/或 `_read_latest_close()`

**技术方案：**
1. 修改 `_save_rating()`：不使用 `_read_latest_close()`（最新 K 线），改为查询 rating_date 对应的 K 线收盘价
2. 查询逻辑：`SELECT close FROM raw_kline WHERE stock_id=? AND trade_date <= ? ORDER BY trade_date DESC LIMIT 1`（rating_date 当日或之前最近交易日）
3. 若查不到 K 线数据，price_at_rating 设为 None（而非使用错误价格）

**验收标准：**
- [ ] 新产生的 ratings_history 记录中，price_at_rating 与 `raw_kline` 中 rating_date 对应收盘价一致（误差 < 0.01）
- [ ] 非交易日运行时，price_at_rating 为最近交易日收盘价
- [ ] 无 K 线数据时 price_at_rating = None

### T3：修复 score_date 来源（P1）

**目标：** score_date 使用 K 线数据的 trade_date，而非 datetime.now()

**修改文件：**
- `modules/scoring_engine.py`：`analyze()` 函数中 score_date 赋值逻辑

**技术方案：**
1. 在 `analyze()` 中，从 `data.trade_date`（StockData 的 K 线日期）提取 score_date
2. `data.trade_date` 格式为 `YYYYMMDD`，需转换为 `YYYY-MM-DD`
3. 回退逻辑：若 `data.trade_date` 为空或无效，使用 `datetime.now()` 作为兜底
4. 确保 `AnalysisResult.score_date` 传播到 `advisor._save_rating()` 的 `rating_date`

**验收标准：**
- [ ] 周六运行分析时，rating_date = 最近交易日（周五），而非周六
- [ ] rating_date 与 raw_kline 中最新 trade_date 一致
- [ ] 回测 `_get_tn_price()` 的 T+1 查找基于正确的交易日

### T4：修复 normalize_rating 旧格式兼容（P1）

**目标：** 旧格式评级（A/B+/B/C/D）与 total_score 矛盾时，优先使用评级字符串映射

**修改文件：**
- `modules/scoring_engine.py`：`normalize_rating()` 函数

**技术方案：**
1. 修改 `normalize_rating()` 逻辑：
   - 若 rating_str 在 RATING_LEGACY_MAP 中（旧格式），**先检查 rating_str 与 total_score 是否一致**
   - 一致（rating_str 映射结果 == _map_rating(score) 结果）：使用 score 精确映射（现有逻辑）
   - **不一致**：使用 RATING_LEGACY_MAP 的字符串映射（评级字符串优先）
   - 无 score 时：直接使用 RATING_LEGACY_MAP（现有逻辑不变）
2. 添加日志：当检测到 rating 与 score 矛盾时，记录 WARNING

**验收标准：**
- [ ] `normalize_rating('D', 74.8)` 返回 `'强烈建议卖出'`（而非 `'推荐买入'`）
- [ ] `normalize_rating('B', 71.9)` 返回 `'持有观望'`（B 映射为持有观望，score 71.9 映射为推荐买入，矛盾时用 B 的映射）
- [ ] `normalize_rating('B+', 78.9)` 返回 `'推荐买入'`（B+ 映射与 score 映射一致）
- [ ] `normalize_rating('推荐买入', 70.1)` 返回 `'推荐买入'`（新格式直接返回，不受影响）
- [ ] 矛盾检测有 WARNING 日志输出

### T5：清理现有回测数据 + 重跑回测（P0）

**目标：** 基于修复后的数据重新生成回测结果

**修改文件：**
- 无代码修改，运维操作

**技术方案：**
1. T1~T4 修复完成后，清空 `backtest_results` 表（真实数据部分，`is_simulated=0 OR is_simulated IS NULL`）
2. 重新执行 `BacktestEngine().batch_backtest(force=True)`
3. 对比修复前后的准确率数据
4. 模拟数据（is_simulated=1）暂不清理，后续单独评估

**验收标准：**
- [ ] 重跑后"推荐买入"回测记录数 ≤ 唯一 (stock_id, rating_date) 组合数
- [ ] 重跑后 price_at_rating 与 K 线收盘价一致
- [ ] 提供修复前后的准确率对比表

### T6（可选）：模拟回测评级映射改进评估
