## 二、测试用例（Q1-Q7）

### Q1：K线同日跳过

**验证目标**：同一只股票同一天第二次分析时，K线采集被跳过

**测试步骤**：
1. 启动 Flask 服务：`python app.py`（在项目目录下）
2. 调用 `POST /api/stocks/<id>/analyze`（选一只已有今日K线的股票）
3. 记录第一次分析的响应和耗时
4. 立即再次调用同一 API
5. 检查第二次分析：
   - 响应中是否包含跳过信息（或通过 DB 验证）
   - 耗时是否明显减少

**DB 验证方法**：
```sql
-- 查询 data_status 中 kline 维度的最新记录
SELECT stock_id, dimension, status, message, fetched_at
FROM data_status
WHERE dimension = 'kline' AND stock_id = <测试stock_id>
ORDER BY fetched_at DESC LIMIT 2;
```
**预期**：最新一条 message 包含"同日跳过"字样

**替代方法**（如 API 无法调用）：直接用 Python 调用 `fetch_kline` 两次：
```python
import sys

sys.path.insert(0, '.')
from modules.data_collector import fetch_kline

# 第一次（可能全量或跳过取决于DB状态）
r1 = fetch_kline('600276', 'a_stock')
# 第二次（应该跳过）
r2 = fetch_kline('600276', 'a_stock')
print(f'第一次: {r1}')
print(f'第二次: {r2}')  # 预期 ('success', '同日跳过(K线已有2026-07-30数据)')
```

**PASS 标准**：第二次调用返回 `('success', 含'同日跳过')`

### Q2：基本面80天财报门控

**验证目标**：财报数据在80天内时跳过财报采集

**测试步骤**：
1. 查询 DB 找一只 report_date 距今 < 80天的股票
2. 调用 `fetch_a_fundamental(symbol)`
3. 检查返回值

**DB 查询**：
```sql
SELECT s.symbol, s.name, rf.report_date,
       julianday('now') - julianday(rf.report_date) as days_ago
FROM raw_fundamental rf
JOIN stocks s ON rf.stock_id = s.id
WHERE s.market = 'a_stock'
GROUP BY s.id
HAVING days_ago < 80
ORDER BY days_ago ASC LIMIT 5;
```

**Python 验证**：
```python
from modules.data_collector import fetch_a_fundamental

# 用上面查到的 symbol
result = fetch_a_fundamental('<symbol>')
print(result)
# 预期：('success', 含'同日跳过' 或 '财报XX天内')
```

**PASS 标准**：返回 success 且消息含跳过字样（或部分跳过时返回 partial 但财报块未重新请求）

### Q6：首次分析兜底

**验证目标**：无数据时（首次分析）不跳过，执行全量采集

**测试方法**：
此场景难以在已有数据的 DB 中直接测试，改为**源码逻辑验证**：

1. 读取 `fetch_kline`（L412）的增量检查逻辑
2. 确认 `if row and row['last_date']:` 包含 None 检查
3. 当 `raw_kline` 中无该 stock_id 记录时 → `row['last_date']` = None → 条件不成立 → 不跳过

**验证范围**：
| 函数 | None 检查行号 | 验证要点 |
|---|---|---|
| fetch_kline | L433 | `if row and row['last_date']:` |
| fetch_a_fundamental | 需确认 | skip_financial 仅当有 last_report_date 时设为 True |
| fetch_sentiment | 需确认 | cnt > 0 时才跳过 |
| fetch_north_capital | 需确认 | 有 fetched_at 时才跳过 |

**PASS 标准**：所有增量检查都有 None 兜底，无数据时不跳过

### Q7：data_status 同日去重

**验证目标**：同一维度同一天只保留最新一条 data_status 记录

**测试步骤**：
1. 查询当前某维度同日记录数
2. 触发同一维度采集3次（如调用 `save_data_status` 3次或分析3次）
3. 再次查询同日记录数

**Python 验证**：
```python
from modules.data_collector import save_data_status
from database.db_manager import get_connection

# 记录前数量
conn = get_connection()
c = conn.cursor()
c.execute("SELECT COUNT(*) FROM data_status WHERE stock_id=1 AND dimension='test'")
before = c.fetchone()[0]

# 触发3次
save_data_status(1, 'test', 'success', 'qa_test_1')
save_data_status(1, 'test', 'success', 'qa_test_2')
save_data_status(1, 'test', 'success', 'qa_test_3')

# 记录后数量
c.execute(
    "SELECT COUNT(*) as cnt, message FROM data_status WHERE stock_id=1 AND dimension='test' GROUP BY message"
)
for r in c.fetchall():
    print(f'  message={r["message"]}, cnt={r["cnt"]}')
conn.close()
```

**预期**：仅1条记录，message = 'qa_test_3'（最新覆盖旧的）

**清理**：
```python
conn = get_connection()
conn.execute("DELETE FROM data_status WHERE stock_id=1 AND dimension='test'")
conn.commit()
conn.close()
```

**PASS 标准**：同维度同日仅1条记录，保留最新message
