## 二、问题描述

### B11-PNL-SIGN（P0）
持仓管理页显示"总浮动盈亏 5116.30"（绿色、无负号），看板页显示"¥-5116.30 (-3.62%)"。同一数据两页符号/颜色矛盾，用户无法判断真实盈亏。

### B11-SCORE-SYNC（P0）
自选股评级列表读 `analysis_results` 表，看板/日报读 `daily_reports` 表。11/27 只股票评分不一致，000858/002352 甚至跨评级档位（持有观望 vs 建议减仓）。

### B11-REPORT-REUSE（P1）
日报生成（daily_report.py L395）对每只股票重新执行 `collect_stock_data()` + `generate_advice()`，与批量分析完全重复。用户先批量分析（5分钟）再生成日报（8.5分钟）= 白等两遍。

### B11-API-DEDUP（P1）
- `stock_financial_analysis_indicator` 单股被调 2 次（fetch_a_fundamental + fetch_fundamental_detail 重复）
- `stock_inner_trade_xq()`（全市场无参数）批量 27 只时调 27 次（应只调 1 次按股票过滤）

### B11-DETAIL-LOAD（P1）
个股详情页首次加载时"投资建议详情"为空、四维显示"暂无关键因子"，需再点"刷新报告"才出内容。

## 三、技术方案

### B11-PNL-SIGN

**排查方向**：
- 持仓页 API：`/api/holdings/summary`（或类似）计算总盈亏
- 看板页 API：`/api/portfolio/summary`（或类似）计算总盈亏
- 对比两处计算公式，找出符号差异根因（可能是 cost_price 方向、quantity 正负、或格式化时丢失负号）

**修复原则**：以数据库实际持仓数据为准，统一计算公式，确保两页输出完全一致。

### B11-SCORE-SYNC

**方案**：将 `/api/ratings`（自选股评级列表）的数据源从 `analysis_results` 改为 `daily_reports`（与看板/日报同源）。

**修改点**：`app.py` 中 `/api/ratings` 路由，将 SQL 查询从 `analysis_results` 表改为读 `daily_reports` 表最新一期数据。

**备选**：如果 `/api/ratings` 有 `analysis_results` 独有的字段需求，则在 `generate_advice()` 写入 `daily_reports` 时同步写入 `analysis_results`（保持两表一致）。

### B11-REPORT-REUSE

**方案**：日报生成时检查当日是否已有有效分析结果，有则跳过采集+评分，直接格式化输出。

**修改 `daily_report.py` `generate_daily_report()` 函数**：
```python
# 在 collect_stock_data + generate_advice 之前增加检查：
cursor.execute(
    'SELECT id FROM daily_reports WHERE stock_id=? AND report_date=? AND status="ok"',
    (stock_id, target_date),
)
if cursor.fetchone():
    # 今日已有有效报告，跳过采集+分析，直接读取已有数据格式化
    existing = cursor.execute('SELECT * FROM daily_reports WHERE stock_id=? AND report_date=?', ...)
    # 直接使用 existing 数据组装日报，不再调 collect_stock_data / generate_advice
    continue
```

**用户感知**：批量分析后点"生成日报"→ 几秒内完成（仅格式化），不再等 8 分钟。

### B11-API-DEDUP

**修改 1**：`fetch_fundamental_detail` 与 `fetch_a_fundamental` 合并调用
- 在 `collect_stock_data()` 中，如果 `fetch_a_fundamental` 已获取到完整数据（非空字段 ≥7），跳过 `fetch_fundamental_detail`
- 或：将两者合并为一个函数，一次 API 调用提取所有字段

**修改 2**：`stock_inner_trade_xq()` 全局缓存
- 该接口无参数（返回全市场数据），在批量分析入口调用 1 次，结果缓存
- 各股票的 `fetch_holder_increase(symbol)` 从缓存中过滤，不再重复调用
- 实现：在 `collect_stock_data()` 外层（批量分析循环前）预取一次，通过参数传入

### B11-DETAIL-LOAD

**排查方向**：详情页 API（`/api/stocks/<id>/report` 或类似）首次加载时读取的数据源可能为空（daily_reports 当日无记录）。

**方案**：详情页加载时，如果 daily_reports 无当日记录，自动触发单只 `generate_advice()`（静默，无需用户点"刷新"），然后返回结果。
