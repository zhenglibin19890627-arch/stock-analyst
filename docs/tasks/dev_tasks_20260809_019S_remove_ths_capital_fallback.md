## 一、需求与裁定

1. **监理裁定（规则级，写入长期约束）**：主力净流入（main_net_inflow）的数据来源链路中，不得使用同花顺数据。
2. 裁定后降级链路变更为：东方财富三层 → 新浪 lscjfb 主力口径（sina_main）→ **估算兜底（is_estimated=1，仅展示不参评）**。即：东财+新浪全失败时，宁可显示"估算"，也不用同花顺全部资金口径冒充主力。
3. **不在本裁定范围（默认保留，待监理另行确认，见第七节开放项 A）**：018 批次引入的 ths_net_inflow 辅助指标列（同花顺净额，用于"主力 vs 散户背离"观察、个股详情展示，不参与评分）。本任务书默认保留该辅助指标，仅移除"顶替主力净流入"的用法。若架构评审或监理认为应一并移除，走开放项 A 裁定。

## 二、现状事实基线（PM 只读核查，2026-08-09）

- capital_source 分布：NULL（东财真数据）3000 行 + 估算 36 行；**ths_total 27 行（23 只股票，日期 08-05×4、08-06×23）**；sina_main 23 行（08-07）。
- 即：历史上 ths_total 顶替只发生在 08-05、08-06 两个东财故障日，涉及面小。

2. **注释/docstring**：fetch_capital_flow docstring（约 L2362–2370 阶梯说明）、前置校验注释（约 L2381–2396）、fetch_capital_flow_batch docstring（约 L1662–1669）等凡提及"第三源=同花顺"的文字全部改为两级阶梯。

4. modules/daily_report.py L174–180 docstring 提及 ths_total 的表述同步修订。

## 三、验收标准（共 6 条）

1. **不再产生新顶替**：任何代码路径不得再写入 capital_source='ths_total' 的行；东财三层+新浪全失败时落回估算兜底（is_estimated=1），链路不断、不抛异常。
2. **防覆盖逻辑不被破坏**：新浪顶替行、东财真数据行的既有保护（不降级、不覆盖）行为逐条回归，对照 019Q 验收结论。
3. **估算兜底回归**：估算行仍 is_estimated=1、仅展示、不参与评分（评分引擎 4 条读取路径过滤不变）。
4. **存量 27 行 ths_total 处置**：由架构评审裁定（候选：a. 保留原样、由既有回补机制在东财恢复时自然覆盖；b. 清空其 main_net_inflow 退回估算展示；c. 其他）。评审未裁定前开发不得擅动。无论选哪种，须有只读核验断言证明处置结果。
5. **回归面**：08-10（周一）定时日报批次不得受影响（当日 16:30 有 019Q 收尾核验定时任务）；开发自测不得在交易日盘中做破坏性实验。
6. **零数据破坏原则**：开发自测一律用只读核验 / :memory: 模拟 / 临时库副本，禁止对生产库做写操作实验。

## 四、风险登记（供架构评审）

1. **R-1 存量行口径**：08-05/08-06 的 27 行 ths_total 曾参与当日评分与日报；追溯重算不在本批次范围（如需，另行裁定）。
2. **R-2 链路缩短的代价**：移除 THS 顶替后，东财+新浪双失败日从"有真实数据参评"变为"估算不参评"，资金面因子当日缺位。这是监理裁定的有意取舍（宁缺毋滥），架构评审确认影响面即可，不需推翻。
3. **R-3 019Q 回补机制耦合**：补采清单与防覆盖 SQL 的 NOT IN ('ths_total','sina_main') 逻辑与 019Q 深度耦合，改动须最小化，评审须逐处核对。
4. **R-4 B11 效应**：非交易日浏览个股详情会触发实时分析写库；自测与 QA 期间禁止点击个股详情。
5. **R-5 辅助指标边界**：ths_net_inflow 辅助列保留与否须明确裁定（开放项 A），防止开发自行扩大/缩小范围。
6. **R-6 注释腐化**：018/019K/019Q 三批次注释互相引用，改动后须全文检索 ths_total / 同花顺 确认无残留误导表述。
