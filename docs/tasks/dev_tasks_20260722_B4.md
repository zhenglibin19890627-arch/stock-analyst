## 技术方案

### 核心逻辑

```
对每只股票（27只）:
  每隔 5 个交易日取一个模拟评级日（约12个时间点/股）:
    1. 截取该日及之前的K线数据（无前瞻偏差）
    2. 运行技术面评分（均线/MACD/RSI/布林带/量价）
    3. 技术面得分 → 映射为评级档位（用现有 RATING_THRESHOLDS）
    4. 用后续真实价格计算 T+1/T+5/T+20 收益率
    5. 用 JUDGEMENT_MATRIX 判定 is_correct
    6. 写入 backtest_results（标记 is_simulated=1）
```

### 关键约束

| 约束 | 说明 |
|---|---|
| **无前瞻偏差** | 模拟评级日 T 只能使用 T 及之前的K线数据 |
| **标记为模拟** | backtest_results 新增 `is_simulated` 列（INTEGER DEFAULT 0），模拟数据=1 |
| **不污染真实数据** | ratings_history 不写入任何模拟记录 |
| **仅技术面** | 模拟评级仅基于 kline 维度得分，不含消息面/资金面/基本面 |
| **评级映射** | 技术面得分直接映射：>=85 强烈推荐买入 / >=70 推荐买入 / >=50 持有观望 / >=30 建议减仓 / <30 强烈建议卖出 |
| **幂等** | 重复执行不产生重复行（UPSERT 或先检查已存在） |

### 模拟时间点选取

- 起始日：最新K线日 - 60 个交易日（约 2026-04-20 附近）
- 间隔：每 5 个交易日一个模拟点
- 每只股票约 12 个模拟点
- 27 只股票 × 12 点 ≈ **324 条模拟回测记录**

### 涉及文件

| 文件 | 变更 |
|---|---|
| `modules/backtest_engine.py` | 新增 `run_historical_simulation()` 函数 |
| `database/db_manager.py` | backtest_results 表新增 `is_simulated` 列（ALTER TABLE） |
| `app.py` | 新增 `POST /api/backtest/simulate` 路由（手动触发） |

### 技术面评分实现

复用现有 scoring_engine.py 中的技术面子项评分逻辑：
- MA 排列（MA5/10/20/60/120/250）
- MACD（金叉/死叉/柱状图）
- RSI（超买/超卖）
- 布林带（位置/开口）
- 量价关系（放量/缩量）

**关键**：传入截止日期的K线切片，而非全量数据。

## 开发方执行要求

1. **无前瞻偏差是核心红线**：模拟评级日 T 只能看到 T 及之前的K线，绝不能使用未来数据
2. **is_simulated 隔离**：所有模拟记录必须标记，UI/API 默认不展示模拟数据（需显式开启）
3. **验收留痕**：完成后在 reports/ 生成自验报告
4. **回归范围**：现有 535 条真实回测不受影响，market-report API 默认行为不变
