## 验收范围（V1-V5，QA 权限内）

### V1：建表成功

**测试要点**：
1. 执行 `python -c "from database.db_manager import init_database; init_database()"` 确认不报错
2. 用 SQL 确认 `alert_rules` 表存在，字段：id/rule_type/stock_id/threshold/enabled/created_at/updated_at
3. 用 SQL 确认 `alert_history` 表存在，字段：id/rule_id/stock_id/alert_type/trigger_value/message/is_read/triggered_at/trigger_date
4. 确认 3 个索引存在：idx_alert_history_unread / idx_alert_history_stock / idx_alert_history_date
5. 确认 UNIQUE 约束 (rule_id, stock_id, trigger_date) 存在
6. 确认默认规则 3 条：rating_change(NULL)/score_below(65.0)/capital_outflow(3)
7. **幂等性**：再次执行 init_database() 不报错，规则不重复

### V2：3类规则可触发

**测试要点**：
1. 执行 `python -c "from modules.alert_engine import scan_once; scan_once()"`
2. 确认 3 类规则均有触发记录写入 alert_history：
   - rating_change（评级跨档）
   - score_below（评分跌破阈值）
   - capital_outflow（主力连续净流出）
3. 抽查至少 1 条记录，确认 message 字段含可读详情（如"评级⬇降级：推荐买入→持有观望"）
4. 抽查至少 1 条记录，确认 trigger_value 字段为合法 JSON

### V3：扫描不破坏日报

**测试要点**：
1. 读 `modules/daily_report.py` 的 `_scheduler_tick` 函数，确认 scan_once() 在 generate_daily_report() 之后调用
2. 确认双层 try/except 隔离：外层（scan_once整体）+ 内层（单只股票循环内）
3. 确认幂等：第二次执行 scan_once()，同规则同股票同日不产生重复记录（对比 INSERT 前后 alert_history 行数）

### V4：API 全通

**测试要点**（启动 Flask 服务后调用，或用 Flask test client）：

| # | 接口 | 方法 | 预期 | 检查点 |
|---|---|---|---|---|
| 1 | `/api/alerts/rules` | GET | 200 + JSON | total≥3，含3条默认规则 |
| 2 | `/api/alerts/unread` | GET | 200 + JSON | unread_count 字段存在，值≥0 |
| 3 | `/api/alerts/rules` | POST | 200 | 新增规则成功，返回新id |
| 4 | `/api/alerts/rules` | POST（非法rule_type） | 400 | 正确拒绝非法类型 |
| 5 | `/api/alerts/rules/<id>` | PUT | 200 | threshold/enabled 可修改 |
| 6 | `/api/alerts/rules/<id>` | DELETE | 200 | 软删除（enabled=0） |
| 7 | `/api/alerts/<id>/read` | POST | 200 | is_read 变为1 |
| 8 | `/api/alerts/read-all` | POST | 200 | 全部 is_read 变为1 |
| 9 | `/api/alerts/scan` | POST | 200 | 手动触发扫描，返回触发数 |

> 注：开发增加了第9个 `/api/alerts/scan` 手动扫描接口，PM已认定合理增强，QA 一并验证。
